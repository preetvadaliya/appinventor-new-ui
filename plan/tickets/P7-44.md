## Summary
The last classic and neo controls that still extend or delegate to a `controls/standard`
class get their own template plus behaviour-only Java, `controls/standard/` is deleted,
and so are the old widgets that only it used. Users see no change.

## Why
- Decision 0013: `StandardControls` is a bridge for P5. It wraps today's widgets so views
  could move to control contracts without a visual change.
- After P5 some layout controls still sit on it: P5-26 lets buttons and menus delegate to
  `Standard*` for behaviour, P5-27 has `ClassicDialog extends StandardDialog`,
  `NeoTree extends StandardTree` and the other dialog and input pieces, and both layouts
  return the standard `Radio` and `Collapsible`.
- While it exists there are three ways to build a control (standard, classic, neo), and
  the old widgets it wraps (`widgets/TextButton`, `widgets/DropDownButton`,
  `widgets/Toolbar`, `widgets/ContextMenu`, `widgets/LabeledTextBox` …) cannot be deleted.

## In scope
- Every class in `layouts/classic/controls/` and `layouts/neo/controls/` that extends or
  imports a `controls.standard` class: give it its own `<Name>.ui.xml` and behaviour-only
  Java, as in `docs/12-patterns.md` 8, rendering the same DOM and class names it renders today
- `ClassicControls`, `NeoControls`: return their own `Radio` and `Collapsible`
- Delete `controls/standard/` and every old widget that nothing else imports once it is
  gone (check each with `grep -r` across `appengine/src` before deleting)
- `appengine/tests/.../ImportRulesTest.java` if P7-40 has landed; otherwise P7-40 adds the
  rule (see Steps)

## Out of scope
- Any visual change, any CSS move (done in P6)
- Old widgets that something outside `controls/standard` still uses
- Nova

## Steps
1. List the classes: `grep -rl "controls.standard" appengine/src/.../client/layouts`.
2. For each, copy the DOM the standard piece renders into a template (every box an
   `HTMLPanel`, prefixes as decision 0008), keep the class names, and move keyboard,
   focus and ARIA code into or onto `controls/behaviour/` so classic and neo share it
   without extending anything.
3. Write `ClassicRadio`/`NeoRadio` and `ClassicCollapsible`/`NeoCollapsible` the same way.
4. Delete `controls/standard/`; then delete each old widget no file imports any more.
5. Make the import-rules test (P7-40) fail on any import of `controls.standard`.
6. If the PR runs over the limit, ship `(1/2)` classic and `(2/2)` neo plus the deletion.

## Acceptance criteria
- [ ] `controls/standard/` does not exist; nothing imports `controls.standard`.
- [ ] Every control in both layouts is a template plus behaviour-only Java.
- [ ] Menus, dialogs, trees and inputs behave by keyboard exactly as before.
- [ ] Snapshot diff shows no change in classic or neo, light or dark.

## Rules
- At most ~400 added lines and ~20 files per PR; deleted lines do not count.
- No visual change. A layout never imports or extends another layout.
- Short conventional commit subjects, e.g. `refactor(controls): neo draws its own dialog`;
  no AI attribution.

## How to verify

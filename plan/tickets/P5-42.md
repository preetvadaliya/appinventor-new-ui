## Summary
The 60 `Command` classes that P3 registered through the transitional
`actions/CommandAction` wrapper become `Action` subclasses in `core/actions/<area>/`,
and `CommandAction` is deleted. Users see no change.

## Why
P3-09 added `CommandAction` so P3-10 to P3-13 could give every menu item an `ActionId`
without rewriting 60 classes at once. Those classes still live in `client/actions/` and
`editor/youngandroid/actions/` and many open dialogs directly. Once the dialogs have
presenters and controls views (P5-28, P5-29, P5-41), an action can start a presenter instead,
which lets it live in `core/` without importing widgets.

## Read first
- `docs/05-actions.md`
- `docs/02-target.md`
- `docs/10-pr-rules.md`

## In scope
- `actions/*.java` (44 files) and `editor/youngandroid/actions/*.java` (16 files), each
  into `core/actions/<area>/` per `docs/file-map.html`
- `actions/CommandAction.java` (deleted)
- `Ode.registerActions()` (registers the new classes)

## Out of scope
- Moving `ActionId`, `Action`, `ActionRegistry` (already in `core/actions` since P3-09)
- Dynamic lists built in code (screens, languages), which stay `Command` items
- Pure package moves of anything else (P7-38)

## Steps
1. Group the actions by area as in `docs/file-map.html` (project, build, connect,
   account, settings, gallery, help, admin, screen, editor).
2. For each class: extend `Action`, move label and `IconKey` from its `CommandAction`
   registration into the constructor, and replace direct widget or dialog creation with
   the matching presenter or `App.views()` call.
3. Ship one PR per two or three areas so each stays under the size limit.
4. Delete `CommandAction` in the last PR.

## Acceptance criteria
- [ ] `client/actions/` and `editor/youngandroid/actions/` are empty and removed.
- [ ] `CommandAction` is gone.
- [ ] Nothing in `core/actions` imports `com.google.gwt.user.client.ui`, `controls`,
      `features` or `layouts`.
- [ ] Every menu and toolbar item still runs the same behaviour.
- [ ] Snapshot diff shows no change in classic or neo, light or dark.

## Rules
- At most ~400 added lines and ~20 files per PR; ship as several PRs by area.
- No visual change.
- Short conventional commit subjects, no AI attribution.

## Summary
Each layout gets an icon set keyed by `IconKey` (P3-09): `layouts/classic/icons/ClassicIcons`
(only the few images and glyphs classic shows today; actions draw as text) and
`layouts/neo/icons/NeoIcons` (Material Symbols names plus neo's own chrome PNGs). Images of
App Inventor components and other designer artwork move behind one shared lookup,
`features/designer/palette/ComponentIcons`, which a layout may override per icon (neo does).
`Ode.getImageBundle()` and the four-way bundle pick go away. Users see no change.

## Why
- `Images.java` (855 lines) declares 137 `ImageResource`s for every purpose:
  92 component icons (`YoungAndroidComponentFactory.java:27-121` and `Mock*` classes),
  10 blocks-drawer icons (`YaBlocksEditor.java:60-68`), 12 phone-frame images used by
  `MockForm` (`phonebar*`, `bookIcon*`), 6 pieces of dialog artwork (`codiVert`
  `Ode.java:1670`; `appInventorLogo` `TemplateUploadWizard.java:867, 906`; `logo`, `wilson`,
  `talkToMeLogo`, `YRLogo` in `explorer/dialogs/NoProjectDialogBox.ui.xml:26, 47, 74, 97`),
  15 chrome images and 2 with no user (`listbox`, `progressbar`).
- Of the 15 chrome images classic shows 9: `help` (`ComponentHelpWidget.java:31`,
  `PropertyHelpWidget.java:77`), `deleteComponent` (`ComponentRemoveWidget.java:22`), `form`
  (screen menu, `DesignToolbar.java:284, 319`), `GetApp` (`ShowBarcodeCommand.java:164`) and
  five `mediaIcon*` (`AssetList.java:148-156`). `boxClose`, `boxMinimize`, `boxRestore`,
  `boxMenu` (`widgets/boxes/Box.java:267, 281, 296, 527, 544`) never show, because every
  `Box` subclass passes `minimizable=false, removable=false`; `close` and `waitingIcon` have
  no user.
- Overrides: `DarkModeImages` 9 (all component icons); `ImagesNeo` 88 (84 component icons,
  `form`, `GetApp`, `listbox`, `progressbar`); `DarkModeImagesNeo` 93 (85 component icons,
  five `mediaIcon*`, `GetApp`, `listbox`, `progressbar`). So component icons are not the same
  in classic and neo today.
- Glyph names are written into templates: 34 `icon="…"` attributes, 30 distinct Material
  names, in 7 templates (the neo project toolbar, design toolbar, top bar, main menu, viewer
  header, and both folder rows, which means classic shows `folder`/`chevron_right` glyphs
  too), plus `expand_more`/`chevron_right` set in Java (`ProjectFolder.java:158, 163`, now
  in the P4-18 folder views).
- `NoProjectDialogBox.ui.xml:13` uses `<ui:with type="…client.Images">`, which creates the
  plain classic light bundle regardless of layout or theme.

## In scope
- New `core/icons/Icon.java` (a picture with an optional dark version, a font glyph, or
  none), `core/icons/BlockCategory.java` (the 10 built-in drawers plus Any component) and
  `core/icons/ComponentIconSource.java` (type, declared `iconName`, extension icon URL);
  see `docs/decisions/0006-icons-images-or-glyphs.md`.
- New `controls/Icons.java`: `action(IconKey)`, `blockCategory(BlockCategory)`,
  `component(ComponentIconSource)`, each returning an `Icon`; `Controls.icons()` returns
  the active layout's set.
- New `controls/IconView.java`: draws any `Icon` (an `<img>` or an `<i>` glyph), swaps a
  picture's dark version on `ThemeChangedEvent`, and labels it for screen readers. It
  replaces `ThemedImage` from P2-07 for icons.
- New `features/blocks/BlockCategoryImages.java`; `YaBlocksEditor.java:60-68` builds its
  `BlocksCategory` list from `BlockCategory`, and `BlockSelectorBox.java:195-197` draws each
  drawer with `IconView` instead of an `<img>` inside an HTML string.
- New `layouts/classic/icons/ClassicIcons.java`, `layouts/neo/icons/NeoIcons.java`;
  `Layout.icons()` in `Layout`, `ClassicLayout`, `NeoLayout`.
- `core/actions/IconKey.java`: add the non-action keys the views need (`FOLDER`,
  `EXPAND`, `COLLAPSE`, `HELP`, `REMOVE`, `SCREEN`, `GET_APP`, `ASSET_IMAGE`,
  `ASSET_AUDIO`, `ASSET_VIDEO`, `ASSET_FONT`, `ASSET_FILE`, `PREVIEW_SIZE`,
  `PREVIEW_DEVICE`, `HIDDEN_COMPONENTS`, `LANGUAGE`, `ACCOUNT`, menu keys …).
- New `features/designer/palette/ComponentIcons.java`: the shared default for component
  icons, ported from `BaseComponentFactory.getImageFromPath` (`BaseComponentFactory.java:249`):
  extension icons from the project's assets, bundled PNGs as static files, anything else as a
  URL. The palette, component tree, non-visible strip and Blocks drawer list ask
  `Controls.active().icons().component(…)` and draw the answer with `IconView`.
- Phone-frame and dialog artwork stay in a small shared image bundle; they are not icons.
- `widgets/ToolbarItem.java`, `widgets/DropDownButton.java`, `components/Icon.java`:
  accept an `IconKey` and resolve it through `Icons.active()`.
- The 7 templates and two Java lines above; the 20 `Ode.getImageBundle()` call sites in 16
  files; `Ode.java:145, 361-363` and the bundle choice in `handleUiPreference`
  (`Ode.java:981-1004`, or wherever P1-04/P2-07 left it); `NoProjectDialogBox.ui.xml`.

## Out of scope
- Moving PNGs into `layouts/*/public/*/icons/` and `features/designer/palette/icons/`, and
  deleting the `Images*` interfaces: they stay as the backing bundles until P7-38/P7-39.
- Drawing classic's actions with icons, or any new glyph.
- SVG/`currentColor` icons (later, per layout).

## Steps
1. `controls/Icons`, the new `IconKey`s, `ClassicIcons` and `NeoIcons`. `NeoIcons.glyph` returns
   the Material names now in the neo templates; `ClassicIcons.glyph` returns the three
   glyphs classic shows (`folder`, `chevron_right`, `expand_more`) and null otherwise.
   Each `image(key)` returns the layout's PNG pair for the 9 chrome images.
2. Boot installs `Icons.install(layout.icons())` next to the controls/layout install.
3. Replace each `icon="name"` with `iconKey="KEY"` (UiBinder's enum attribute parser) and
   the two Java glyph strings with keys.
4. `ComponentIcons.get(path)` asks `Icons.active().componentIcon(path)` first, then the
   shared default (`Images` light, `DarkModeImages` dark). `NeoIcons.componentIcon`
   returns neo's 84/85 overrides. Route the 16 files through `ComponentIcons` or
   `Icons.active().image(…)`; delete `Ode.getImageBundle()` and `IMAGES`.
5. Remove the unused `close`, `waitingIcon`, `listbox`, `progressbar` and the four box
   images if P0-01 has not already (no call sites, no visual effect).
6. Add `IconsTest`: every `IconKey` used by an action or view template has a glyph in
   `NeoIcons`; `ClassicIcons` maps the keys classic templates name.

## Acceptance criteria
- [ ] No `icon="…"` glyph name remains in any template; glyph strings exist only in
      `layouts/*/icons/`.
- [ ] `grep -r getImageBundle client/` is empty.
- [ ] Classic component icons come from the shared set, neo's from its overrides; light and
      dark both switch live (P2-07) in each.
- [ ] Every `Icons` method may answer with a picture or a glyph: a unit test runs the
      palette row and the drawer list against a fake icon set that returns only glyphs and
      one that returns only pictures, and both render.
- [ ] An extension's icon shows in classic and neo exactly as today, including in the
      component tree and the Blocks editor's list.
- [ ] `IconsTest` passes under `ant tests`.
- [ ] Snapshot diff shows no change in classic or neo, light or dark.

## Rules
- Icons are `IconKey`s outside a layout's icon set; no layout imports another.
- At most ~400 added lines and ~20 files. Split on the ticket first: P4-22a glyphs by key
  (steps 1-3, 6) and P4-22b images by key (steps 4-5).
- Branches `ui/p4-22a-glyph-keys`, `ui/p4-22b-image-keys`; PR titles
  `[new-ui P4-22] Each layout has its own icon set (1/2)` and `(2/2)`; commits like
  `refactor(icons): icon set per layout`; no AI attribution.

## Summary
`war/static/css/Ya.css` and the `Ode.Resources` CSS bundle are deleted. `index.jsp` links
only shared CSS, and `LayoutRegistry` adds the active layout's `tokens.css`, `controls.css` and
`views.css`. No global stylesheet carries layout rules any more. Nothing looks different.

## Why
On master every page links `Ya.css` (`war/index.jsp:75`, 4,137 lines) and `Ode` injects
one of four `CssResource`s: `Ode.Resources` (`Ode.java:2753-2783`) pairs a token file with
`layouts/classic/public/classic/variableColors.css` (1,230 lines) or `layouts/neo/public/neo/neo.css` (2,145 lines);
`initializeUi` picks one and calls `style.ensureInjected()` (`Ode.java:1055-1072`); the
`style` field (`Ode.java:259`, `@UiField(provided = true) static Resources.Style style`)
feeds `<ui:with field="style" />` in `Ode.ui.xml:15` and `style/neo/Ode.ui.xml:15`.
P6-33 to P6-36 emptied all three rules files; this ticket removes what is left.

## Steps
1. Check that `Ya.css` and the rules files hold no rule (only comments). If a rule is left,
   move it under the ticket that owns its area before deleting.
2. Delete the files and the bundle code listed above.
3. `index.jsp` keeps, in order: `gwt.css`, `blockly.css`, `ai2blockly.css`, Font Awesome,
   three Leaflet sheets, `ode/features/base.css`, the four `ode/mocks/*.css` skins,
   `fonts.css`, `nano.min.css`. The `Ya.css` link (75) is removed.
4. `LayoutRegistry` appends, after those links, `<link>`s for the active layout's
   `stylesheets()` (`tokens.css`, `controls.css`, `views.css`), built from
   `GWT.getModuleBaseURL()` so `ode.base` (the CDN flag read at `index.jsp:42`) keeps
   working. Add a version query (for example the build id) because the names are not
   hashed and `appengine-web.xml` caches by path.
5. `Ya_tos_form.html` links `ode/features/base.css` instead of `static/css/Ya.css`; it
   needs only `.floatingBox`.

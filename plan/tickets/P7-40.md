## Summary
A plain JUnit test scans the client sources and fails when one of the five structure
rules breaks, and an ant target makes that failure stop `ant tests` and CI. From here on a
PR cannot quietly make neo depend on classic again, or put widgets into `core/`.

## Why
The rules in `docs/02-target.md` hold after P7-39 only by review. Client tests live in
`appengine/tests/com/google/appinventor/client/` (7 files on master) and run through
`AiClientLibTests` (`appengine/build.xml:754-761`), which calls the `ai.dojunit` macro
(`build-common.xml:178`). That macro runs JUnit with `haltonfailure="no"` (line 219), so a
failing test only shows in the report; CI (`.github/workflows/ant.yml`, step "Run Tests",
`ant tests`) stays green. On master, 9 files bound for `core/` import GWT widgets
(`AboutAction`, `AboutCompanionAction`, `ShowShortcutsAction`,
`CopyYoungAndroidProjectCommand`, `DeleteFileCommand`, `LocalUploader`, `Downloader`,
`Uploader`, `YoungAndroidFormUpgrader`) and 35 import a class bound for `features/`,
`controls/` or `layouts/`; P3 to P5 should have removed most of these.

## Steps
1. Write `ImportRulesTest` with plain `java.nio.file`, reading
   `src/com/google/appinventor/client` relative to the working directory (`appengine`, as
   `ai.dojunit` sets `dir="${basedir}"`). Strip comments, then check imports, fully
   qualified names, JSNI `@…::` references and `urn:import:` namespaces:
   1. `core/**`: no `com.google.gwt.user.client.ui.`, `com.google.gwt.uibinder.`,
      `com.google.gwt.resources.client.` or `com.google.gwt.dom.client.`; nothing from
      `client.controls`, `client.features`, `client.layouts`; no `.ui.xml` or `.css` files.
   2. `features/**`: nothing from `client.layouts`.
   3. `layouts/<x>/**`: nothing from `client.layouts.<y>` for any other `y`; CSS under
      `layouts/<x>/public/` has no `@import` or `url()` into another layout's folder.
   4. CSS: `war/index.jsp` links no file under a layout's public folder and no `Ya.css`;
      no `CssResource` with a `.css` `@Source` remains in `client/`; every `.css` string
      in `layouts/<x>/**/*.java` starts with `<x>/`.
   5. Actions: no Java file contains `WIDGET_NAME_` or calls `setButtonEnabled`,
      `setItemEnabled`, `setDropDownButtonVisible` with a string literal; no `.ui.xml`
      toolbar or menu item has `name=` without `action=`.
2. Report every violation as `file:line rule message`, not just the first.
3. Keep an `ALLOWED` list in the test for violations that need a code change outside this
   ticket; each entry names a follow-up issue. It may only shrink.
4. Add `CheckImportRules` to `appengine/build.xml`: depends on `AiClientLibTests`, runs
   only `com.google.appinventor.client.ImportRulesTest` from `AiClientLibTests.jar` with
   `haltonfailure="yes"`; make `tests` depend on it so `ant tests` fails.

## Acceptance criteria
- [ ] `ant tests` passes on the branch and fails when any one rule is broken.
- [ ] For each rule, a deliberate violation (a temporary import of `NeoButton` into
      `layouts/classic`, a `Button` import into `core`, …) fails with a message naming the
      file, line and rule; recorded in the PR description.
- [ ] The test runs in under 5 seconds and needs no GWT compile.
- [ ] `ALLOWED` is empty, or each entry links an open issue.

## Rules
- At most ~400 added lines and ~20 files.
- No production code changes except removing a violation that is a one-line import fix.
- Short conventional commit subjects, e.g. `test(client): enforce package import rules`;
  no AI attribution.

## How to verify
- `ant checkstyle -Dcommit=upstream/master`: no warnings on changed lines
  (`docs/13-code-style.md`)
- `cd appengine && ant CheckImportRules`
- `ant -Dtest_name=com.google.appinventor.client.ImportRulesTest AiClientLibTests`, then
  read `appengine/reports/html/index.html`
- From the repository root, `ant tests` to see it wired into the full run.

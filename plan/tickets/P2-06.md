## Summary
Neo's colours and images become CSS custom properties in a static
`layouts/neo/public/neo/tokens.css` (light on `:root`, dark on `:root[data-theme="dark"]`), and
`neo.css` leaves the GWT `ClientBundle` as a static file that reads them with `var(--name)`.
Neo looks exactly as before, in light and dark.

## Why
- Neo's tokens are GWT `@def` constants: `style/neo/lightNeo.css` (62 lines, 39 `@def`s) and
  `style/neo/darkNeo.css` (59 lines, 39). Only light has `closed-backpack`; only dark has
  `v-white-shadow`. They are compiled with `style/neo/neo.css` (2,145 lines) into two bundles,
  `Ode.Resources.stylemodernLight()` / `stylemodernDark()` (`Ode.java:2769-2779`), so light and
  dark cannot change without a reload.
- GWT's `CssResource` substitutes a `@def` wherever its bare name appears in a value. `neo.css`
  uses 36 of the 40 names, 316 times on 313 lines, always as bare identifiers: no `value()`,
  `@sprite`, `@if`, `@eval`, `literal()`, `@url` or `@media`. The `@import` of Droid Sans at
  line 12 sits inside a comment (lines 9-13).
- Line 15 is `@external .*;`, so class names are already unobfuscated; no template or Java code
  changes for the move. `Ode.Resources.Style` declares no methods.
- 11 light and 10 dark tokens are `url('static/images/…')` (light's `closed-backpack` is
  `url('../blocklyeditor/…')`). Injected as a `<style>`, they resolve against the page today;
  from a file under `/ode/neo/` they would resolve against the file.
- `neo.css:561` has a literal `url(../images/toolbarBG.png)`. Against the page it points at
  `/images/toolbarBG.png`, which does not exist (the file is `war/static/images/`), so the
  status bar has no background image today.

## Steps
1. Write `tokens.css`: every `@def name value;` becomes `--name: value;`, light values under
   `:root`, dark under `:root[data-theme="dark"]`. Carry over every token, including the four
   `neo.css` never uses (`background-image`, `closed-backpack`, `clr-primary-75`,
   `v-white-shadow`).
2. Rewrite each relative `url('static/…')` as `url('../../static/…')` (served at `/ode/neo/`).
   Both files sit in the same folder, so the result is the same whichever stylesheet a browser
   resolves a `var()` URL against. Leave `neo.css:561` as it is: it stays a 404.
3. Convert the rules with a throw-away script (do not commit it): inside declaration values
   only, replace each defined token name with `var(--name)`; never touch property names or
   selectors, and leave words that are not defined tokens alone.
4. Delete `@external .*;` and the commented `@import` block. Check that no `@def` or bare token
   name is left.
5. Wire the files through `NeoLayout.stylesheets()`; P1-04's loader adds the links after
   `Ya.css` and waits for them.

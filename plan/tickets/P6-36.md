## Summary
The rules for each layout's building blocks (buttons, toolbars, menus, dialog frame, popups,
progress bar, inputs) live in `layouts/classic/public/classic/controls.css` and
`layouts/neo/public/neo/controls.css`, loaded only for the active layout. Nothing looks
different.

## Why
After P5-27 classic and neo each draw their own controls (`ClassicButton`, `NeoDialog` …), but
the control rules still come from the global `war/static/css/Ya.css` plus the rules file
compiled into `Ode.Resources`. In `Ya.css`, about 106 rules (~790 lines):
- 92-139 GWT button defaults: `.gwt-PushButton-*`, `.gwt-Button*`, `.gwt-RadioButton` (8)
- 166-249 context menus `.ode-ContextMenu*` (12)
- 710-753 `.ActionDropDown-Default`, `.ActionDropDown-Options`, in selector lists shared
  with `.ode-TopPanelButton` (frame, P6-35)
- 997-1067 GWT widget defaults: `.gwt-TabBar*`, split panels, `.gwt-TextBox`, `.gwt-Tree*` (14)
- 1068-1220 `.ya-Toolbar`, `.ode-TextButton`, `.gwt-Button`, `.destructive-action`,
  `.ode-PanelButtons` (14); 3729-3756 `.ya-Toolbar` alignment, `.ya-ProjectName` (6)
- 2275-2416 dialog frame: `.ode-DialogBox`, `.Caption`, `.dialogTop`, `.dialogContent`,
  `.ode-DialogRow`, `.ode-WizardContent`, `.ode-DialogButtons` (25)
- 2506-2558 `.gwt-ProgressBar-shell`, `.gwt-PopupPanel`, `.gwt-PopupPanelGlass` (5)
- 2559-2771 inputs, `select`, `textarea`, `.radio`/`.checkbox`, Bootstrap-derived (22)

About 41 rules in `layouts/classic/public/classic/variableColors.css` and 73 in `layouts/neo/public/neo/neo.css`
restyle these classes. `neo.css` adds neo-only control rules: `.ode-ProjectListButton*`,
`.bleft`/`.bright`/`.bcenter`, `.danger`, `.action`, `.raised`, `.ode-FormCheckboxLabel`.

## In scope
Paths are as they are after P2-05 and P2-06, which move `style/classic/variableColors.css`
and `style/neo/neo.css` into the layouts' public folders.
- `war/static/css/Ya.css`: the ranges above
- `layouts/classic/public/classic/variableColors.css`, `layouts/neo/public/neo/neo.css`: control rules
- `layouts/classic/public/classic/controls.css`, `layouts/neo/public/neo/controls.css` (new)
- `ClassicLayout.stylesheets()`, `NeoLayout.stylesheets()`

## Out of scope
- Rules for one dialog's contents (`.uploadDialogContent`, `.lie-*`, `.ode-noDialog*`): P6-34
- `war/static/css/gwt.css` (1,153 lines, GWT's own defaults): stays shared and linked
- Frame rules (P6-35); deleting `Ya.css` and `Ode.Resources` (P6-37)

## Steps
1. Make `stylesheets()` return `tokens.css`, `controls.css`, `views/shell.css`,
   `views/projects.css`, `views/editor.css` in that order (as in `docs/12-patterns.md` 7), so a view rule can still override a control rule as today.
2. For each control rule in `Ya.css`, copy it into both `controls.css` files, merge that layout's
   override from `variableColors.css` or `neo.css`, delete the originals. Move the
   neo-only and classic-only control rules too.
3. Split the shared selector lists at 710-753 so only `.ActionDropDown-*` moves here.
4. If P5-26/P5-27 gave controls new class names, keep the old names in the moved
   selectors only where markup still uses them; drop dead ones.
5. Check the dialog overrides of the layout helpers
   (`.ode-DialogBox .dialogContent .ode-Layout-spacing*`, `Ya.css:2370-2392`) still win
   over the helpers in `dialogs.css` (P6-34).

## Acceptance criteria
- [ ] `Ya.css`, `variableColors.css` and `neo.css` have no control rule left.
- [ ] Classic loads only classic's `controls.css`, neo only neo's.
- [ ] Neither `controls.css` refers to the other layout's folder or class names.
- [ ] Buttons (normal, hover, active, disabled, destructive), dropdowns, context menus,
      dialogs and wizards, inputs with focus rings, progress bar and modal glass look as
      before.
- [ ] Snapshot diff shows no change in classic or neo, light or dark.

## Rules
- At most ~400 new lines and ~20 files. Rules moved verbatim (`git diff --color-moved`)
  do not count, but the second copy of each control rule does; if needed, split into `(1/2)`
  buttons, toolbars, menus and `(2/2)` dialog frame, popups, inputs.
- No visual change. Fix cascade ties with specificity, never `!important`.
- A layout never imports or extends another layout, CSS included.
- Short conventional commit subjects, e.g. `refactor(css): classic control rules move to controls.css`;
  no AI attribution.

## How to verify
- `ant -Dskip.ios=true noplay`, `ant tests`, `ant BlocklyTest`
- Snapshot screens: New project dialog, Project properties dialog, Designer toolbar, a
  menu open (classic/neo × light/dark)
- By hand: tab through a dialog and a toolbar to see focus rings; right-click a project
  for the context menu; open a wizard with Back/Next; start a build to see the progress bar.

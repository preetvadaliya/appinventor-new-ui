## Summary
A new `core/presenters/ProjectListPresenter` owns sorting, selection, folder expand/collapse,
the trash switch and the project counts, once for both layouts. The folder data (name,
dates, projects, child folders, JSON) leaves the `ProjectFolder` widget for a plain model,
`core/project/folders/Folder`. `ProjectList`, `ProjectListItem`, `ProjectFolder` and their
neo subclasses keep only rendering; they stay where they are until P4-18. Users see no change.

## Why
- `explorer/folder/ProjectFolder.java` (464 lines) is both the folder model and a
  `Composite`. `FolderManager` builds the model through the style factory
  (`FolderManager.java:33-36, 64, 81, 126-129`, `uiFactory.createProjectFolder`), so the
  saved folder tree is made of widgets, and `Project.homeFolder` (`Project.java:41, 163-169`)
  points at a widget.
- Selection lives in checkboxes: `ProjectListItem.isSelected()` (`ProjectListItem.java:74-76`)
  and `ProjectFolder.isSelected()` (`ProjectFolder.java:254-256`) read `checkBox.getValue()`,
  and the counts walk rendered rows (`projectListItems`, `ProjectFolder.java:55, 278-294`).
- Sorting, select-all and trash logic sit in the classic view (`ProjectList.java:161-204,
  323-395`) and are inherited by `style/neo/ProjectListNeo.java`.
- Nine callers reach into the widget for data: `DeleteAction.java:30-32`,
  `DeleteForeverProjectAction.java:29-32`, `RestoreProjectAction.java:25-28`,
  `ExportProjectAction.java:29`, `SendToGalleryAction.java:54`,
  `MoveProjectsWizard.java:56-58`, `TopToolbar.java:326`, `HTML5DragDrop.java:305-306`,
  `Ode.java:812, 1909`.

## Steps
1. `Folder`: a plain class (no GWT widget imports) with the data methods in the table.
   `FolderManager` creates `Folder`s directly; delete the three `createProjectFolder`
   overloads from `UiStyleFactory` and `UiFactoryNeo` and the factory field in
   `FolderManager`. Retype `Project.homeFolder`, the comparators, wizards and actions.
2. `ProjectList` builds a folder row per `Folder` (`createFolderRow(Folder)`, overridden by
   `ProjectListNeo` and `ProjectFolderNeo` to return the neo row, like
   `createProjectListItem` today).
3. `ProjectListPresenter` with a nested `View`:
   `render(Node root)` (an ordered tree of folders and projects, each folder with its
   expanded flag), `setSelected(Project, boolean)`, `setSelected(Folder, boolean)`,
   `setExpanded(Folder, boolean)`, `setSelectAll(boolean)`, `showSort(SortField, boolean
   ascending)`. The view reports `onProjectChecked`, `onFolderChecked`,
   `onFolderExpandToggled`, `onSelectAllChecked`, `onSortClicked`, `onOpenProject`.
   The presenter keeps `Set<Project>`, `Set<Folder>` selected and `Set<Folder>` expanded,
   and fires a selection-changed event that `ProjectToolbarPresenter` (P3-10) and the main
   menu listen to.
4. Public queries callers need: `getSelectedProjects()`, `getSelectedFolders()`,
   `getSelectedCount()` (projects + folders, as `ProjectList.java:358-364`),
   `getMyProjectsCount()`, `showProjects()`, `showTrash()`. Point the nine callers at them.
5. Strip the moved code from the six views; `ProjectListBox.loadProjectList()` and
   `loadTrashList()` (`ProjectListBox.java:72-82`) call the presenter.
6. Unit-test the presenter with a fake `View`: sort cycling, select-all, expand clears the
   folder's selection, hidden rows not counted, read of counts in trash.

## Acceptance criteria
- [ ] `Folder` and `ProjectListPresenter` import no `com.google.gwt.user.client.ui` class
      and nothing from `layouts/`, `kit/` or `features/`.
- [ ] No view decides anything: sort order, select-all state, counts and trash handling come
      from the presenter.
- [ ] `FolderManager` no longer takes a `UiStyleFactory`; `createProjectFolder` is gone.
- [ ] Saved folder JSON is byte-for-byte the same before and after (check with a user who
      has nested folders and trashed projects).
- [ ] `ProjectListPresenterTest` passes under `ant tests`.
- [ ] Snapshot diff shows no change in classic or neo, light or dark.

## Rules
- Preserve today's behaviour, including: a refresh clears all selection
  (`ProjectFolder.java:193`, new rows); expanding a folder unchecks and hides its checkbox
  (`ProjectFolder.java:154-168`); projects inside collapsed folders are not counted
  (`ProjectFolder.java:289-291`); the root list always sorts its projects while child
  folders sort only when asked (`ProjectList.java:301` vs `ProjectFolder.java:207-209`);
  date-created ascending sorts folders by date modified (`ProjectList.java:186`). File
  the last two as follow-ups instead of fixing them here.
- At most ~400 added lines and ~20 files. This will not fit in one PR: land it as
  P4-17a "Folder model leaves the widget" (step 1-2, about 19 files, no behaviour change)
  and P4-17b "Project list presenter" (steps 3-6). Record the split on the ticket first.
- Branches `ui/p4-17a-folder-model`, `ui/p4-17b-project-list-presenter`; PR titles
  `[new-ui P4-17] Project list logic lives in a presenter (1/2)` and `(2/2)`; commits like
  `refactor(projects): folder model leaves the widget`; no AI attribution.

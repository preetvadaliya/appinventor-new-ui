## Summary
The designer toolbar becomes `layouts/classic/views/editor/ClassicDesignToolbar` and
`layouts/neo/views/editor/NeoDesignToolbar`, both implementing
`DesignToolbarPresenter.View`; the screen and editor-switching state moves out of the
widget into `core/presenters/DesignToolbarPresenter`. Neo's hard-coded "Screens:" caption is
translated. Users see no change. The viewer header (preview size, phone preview, hidden
components) is not touched here: it becomes part of each layout's viewer region in P5-43.

## Why
- `style/neo/DesignToolbarNeo.java` (48 lines) extends `editor/youngandroid/DesignToolbar.java`
  (433 lines), re-declares 8 `@UiField`s (`DesignToolbarNeo.java:23-30`) and copies them back
  (`:39-46`). Its `bindUI()` declares a local `boolean isAvailable` (`:37`) that hides the
  field, then copies the local to `super.isAvailable` (`:45`). `backArrow` is declared in
  the classic class (`DesignToolbar.java:47`) but exists only in neo's template.
- `DesignToolbar` is both widget and model: `DesignProject`/`Screen` (`:54-114`), the
  project map and companion screen stack (`:139-148, 330-359`), switching
  (`:192-306, 361-394`), the Designer/Blocks toggle (`:396-403`) and a global Ctrl+Alt key
  handler (`:405-419`). 19 other files name the `DesignToolbar` type.
- `style/neo/DesignToolbarNeo.ui.xml:23` has
  `<ai:ToolbarItem … caption="Screens: " …/>`, an English string outside `OdeMessages`.

## Steps
1. Move `DesignProject`, `Screen`, `EditorPair`, the project map, the screen stack and the
   switching methods into `DesignToolbarPresenter`, keeping method names so callers change
   only the type. The `DesignToolbar.View` enum (`DESIGNER`, `BLOCKS`) becomes
   `DesignToolbarPresenter.Editor`, since `View` names the view interface.
2. `View` methods: `showProjectName(String)`, `showScreens(List<String>, String current)`,
   `showCurrentScreen(String)`; enable/visible stay on actions (P3-13).
3. `ClassicDesignToolbar` and `NeoDesignToolbar` each extend `Composite`, own a `Binder`
   and implement the `View`. Template per decision 0008: a `<g:HTMLPanel styleName="row
   items-center …">` root holding the project name label and today's `<ai:Toolbar>` with its
   `ToolbarItem`s (a `ToolbarItem` works only inside a `Toolbar`) until P5-26 swaps them
   for the layout's buttons in flex `HTMLPanel`s. Keep today's style names next to the flex
   classes. Neo keeps `backArrow` and its icons; classic has none.
4. Add `@DefaultMessage("Screens: ") @Description("Label before the screen picker in the
   designer toolbar.") String screensLabel();` to `OdeMessages` and use
   `caption="{messages.screensLabel}"` in `NeoDesignToolbar.ui.xml`.
5. Wire in `Ode` with the P4-15 pattern (`provided = true` field from the layout) until
   P4-21 moves the slot into the editor page.

## Acceptance criteria
- [ ] Both toolbars have their own `<g:HTMLPanel>`-rooted template; neither extends the
      other or `widgets/Toolbar`; no `super.x = x` left in designer views.
- [ ] `DesignToolbarPresenter` imports no GWT widget class.
- [ ] Neo shows "Screens:" from `OdeMessages.screensLabel()`; no literal caption remains in
      any designer template.
- [ ] Switching screens, adding/removing a screen, Designer/Blocks buttons and Ctrl+Alt
      toggling work in both layouts; Remove Screen is disabled on Screen1.
- [ ] Snapshot diff shows no change in classic or neo, light or dark.

## Rules

- Templates follow decision 0008 (every box an `HTMLPanel`, no raw `<div>`/`<span>`, `addStyleNames` on

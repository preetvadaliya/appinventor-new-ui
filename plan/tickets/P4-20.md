## Summary
The designer toolbar becomes `layouts/classic/views/designer/ClassicDesignToolbar` and
`layouts/neo/views/designer/NeoDesignToolbar`, both implementing
`DesignToolbarPresenter.View`; the screen and editor-switching state moves out of the
widget into `core/presenters/DesignToolbarPresenter`. The viewer header (preview size,
phone preview, hidden-components checkbox) becomes the shared
`features/designer/ViewerHeader`, used by classic, with neo supplying
`layouts/neo/views/designer/NeoViewerHeader`. Neo's hard-coded "Screens:" caption is
translated. Users see no change.

## Why
- `style/neo/DesignToolbarNeo.java` (48 lines) extends `editor/youngandroid/DesignToolbar.java`
  (433 lines), re-declares 8 `@UiField`s (`DesignToolbarNeo.java:23-30`) and copies them back
  (`:39-46`). Its `bindUI()` declares a local `boolean isAvailable` (`:37`) that hides the
  field, then copies the local to `super.isAvailable` (`:45`). `backArrow` is declared in
  the classic class (`DesignToolbar.java:47`) but exists only in neo's template.
- `DesignToolbar` is both widget and model: `DesignProject`/`Screen` (`:54-114`), the
  project map and companion screen stack (`:139-148, 330-359`), switching
  (`:192-306, 361-394`), the Designer/Blocks toggle (`:396-403`) and a global Ctrl+Alt key
  handler (`:405-419`). 19 other files name the `DesignToolbar` type.
- `style/neo/DesignToolbarNeo.ui.xml:23` has
  `<ai:ToolbarItem … caption="Screens: " …/>`, an English string outside `OdeMessages`.
- `style/neo/YaVisibleComponentsPanelNeo.java` (98 lines) extends
  `editor/youngandroid/YaVisibleComponentsPanel.java` (259 lines), re-declares 6 fields
  (`:24-29`), copies 4 back (`:93-96`) and copies the parent's `initializeListboxes`
  (`:37-73` vs `YaVisibleComponentsPanel.java:91-125`) only to toggle two icons. It is
  created by `UiStyleFactory.createSimpleVisibleComponentsPanel` (`UiStyleFactory.java:56-59`,
  `UiFactoryNeo.java:38-42`), reached through `ProjectEditor.getUiFactory()`
  (`ProjectEditor.java:108-110`) from `YaFormEditor.java:97`.

## Steps
1. Move `DesignProject`, `Screen`, `EditorPair`, the project map, the screen stack and the
   switching methods into `DesignToolbarPresenter`, keeping method names so callers change
   only the type. The `DesignToolbar.View` enum (`DESIGNER`, `BLOCKS`) becomes
   `DesignToolbarPresenter.Editor`, since `View` names the view interface.
2. `View` methods: `showProjectName(String)`, `showScreens(List<String>, String current)`,
   `showCurrentScreen(String)`; enable/visible stay on actions (P3-13).
3. `ClassicDesignToolbar` and `NeoDesignToolbar` each extend `widgets.Toolbar`, own a
   `Binder`, implement the `View`. Neo keeps `backArrow` and its icons; classic has none.
4. Add `@DefaultMessage("Screens: ") @Description("Label before the screen picker in the
   designer toolbar.") String screensLabel();` to `OdeMessages` and use
   `caption="{messages.screensLabel}"` in `NeoDesignToolbar.ui.xml`.
5. `ViewerHeader` keeps all logic of `YaVisibleComponentsPanel` and declares
   `interface View extends IsWidget` (form slot, size list, preview list, hidden checkbox,
   `setSizeIconVisible`, `setPreviewIconVisible`). Its default view uses
   `ViewerHeader.ui.xml`; `NeoViewerHeader` implements `View` with neo's template. Replace
   the `ListBox` subclasses with attach handlers so no view overrides logic.

## Acceptance criteria
- [ ] No class in `layouts/neo/views/designer` extends a classic or shared view class;
      no `super.x = x` left in designer views.
- [ ] `DesignToolbarPresenter` imports no GWT widget class.
- [ ] Neo shows "Screens:" from `OdeMessages.screensLabel()`; no literal caption remains in
      any designer template.
- [ ] Switching screens, adding/removing a screen, Designer/Blocks buttons and Ctrl+Alt
      toggling work in both layouts; Remove Screen is disabled on Screen1.
- [ ] Preview size, phone preview and "Display hidden components" behave as before,
      including Fixed sizing and the Classic theme.
- [ ] Snapshot diff shows no change in classic or neo, light or dark.

## Rules
- At most ~400 added lines and ~20 files: land it as two PRs, P4-20a (steps 1-4) and
  P4-20b (step 5); `git mv` templates so they show as renames.
- A layout never imports another layout; `features/designer/ViewerHeader` names no layout.
- Branches `ui/p4-20a-design-toolbar-views`, `ui/p4-20b-viewer-header`; PR titles
  `[new-ui P4-20] Each layout has its own design toolbar (1/2)` and `(2/2)`; commits like
  `refactor(views): design toolbar per layout`; no AI attribution.

## Summary
Every kind of property editor gets one shared default view in
`features/properties/editors/` (`ChoiceEditorView`, `TextEditorView`, `NumberEditorView`,
`BooleanEditorView`, `ColorEditorView`, `AssetEditorView` …), built only from control
interfaces, so it draws with `ClassicSelect` in classic and `NeoSelect` in neo. Each view
implements the `View` interface of its model in `core/properties/editors/` (decision 0011).
Today's editor classes keep their logic and drive these views instead of raw GWT widgets;
P5-31 then moves that logic into the models. Classic and neo look and behave as before.

## Why
- `widgets/properties/` has 23 Java files. Seven construct raw widgets, 35 in total:
  `SubsetJSONPropertyEditor` 24 (8 `Button`, 7 `CheckBox`, 2 `Tree`, 1 `TreeItem`,
  2 `PopupPanel`, 1 `DropDownButton`, 1 `DialogBox`, 1 `TextBox`, 1 `FileUpload`),
  `AdditionalChoicePropertyEditor` 4 (lines 42, 70, 77, 96), `ChoicePropertyEditor` 3
  (`new DropDownButton(` at lines 122, 138, 188), `BooleanPropertyEditor` 1 (line 37),
  `ColorChoicePropertyEditor` 1 (`new TextButton()`, line 69), `TextPropertyEditor` 1
  (line 18), `TextAreaPropertyEditor` 1. `TextPropertyEditorBase` (200 lines) takes a GWT
  `TextBoxBase` in its constructor (line 52).
- In `editor/youngandroid/properties/`, raw widget constructions remain in 12 files, 30 in
  total: `YoungAndroidLengthPropertyEditor` 6 (4 `RadioButton` at lines 60-63, 2
  `TextBox`), `ListViewAddDataDialog.ui.xml` 6, `ListViewDataRow.ui.xml` 3,
  `YoungAndroidGeoJSONPropertyEditor` 3, `ListViewAddDataDialog.java` 2,
  `YoungAndroidAssetSelectorPropertyEditor` 2, `YoungAndroidFontTypefaceChoicePropertyEditor`
  2, `YoungAndroidDefaultURLPropertyEditor` 2, `YoungAndroidComponentSelectorPropertyEditor`
  1, `YoungAndroidDataColumnSelectorProperty` 1, `YoungAndroidListViewAddDataPropertyEditor`
  1, `YoungAndroidSpriteOriginPropertyEditor` 1. Five list editors use `ListBox` in list
  mode through `ListWithNone.ListBoxWrapper` (`ListWithNone.java:19`).
- Widget code and value checks sit in the same classes, so neither a layout nor a test can
  reach one without the other.

## In scope
- New `core/properties/editors/<Kind>EditorModel.java`, for now holding only the nested
  `View` interface (P5-31 adds the logic): one per kind of editor, about a dozen
  (choice, text, number, boolean, color, asset, component, length, GeoJSON, default URL,
  list data, sprite origin, blocks subset).
- New `features/properties/editors/<Kind>EditorView.ui.xml` + `.java`, one pair per model,
  built from control elements (`Select`, `TextField`, `Checkbox`, `Radio`, `Button`, `MenuButton`,
  `Tree`, `Dialog`).
- Edited to drive a view instead of widgets: the seven generic editors above,
  `PropertyHelpWidget` (help popup as a `Dialog`), `ListWithNone`, the nine component
  editors above, `ListViewAddDataDialog` and `ListViewDataRow` (`.java` + `.ui.xml`).

## Out of scope
- Editor logic, the 36 choice lists and `PropertyEditors.forType` (P5-31).
- The properties panel, its categories (`CollapsibleCategoryPanel`) and property rows:
  they become `ClassicProperties`/`ClassicPropertyRow` and the neo equivalents in P5-43.
- The two `PopupPanel`s that anchor editors under a row
  (`AdditionalChoicePropertyEditor.java:96`, `SubsetJSONPropertyEditor.java:91`) and
  `ListViewDataRow.AssetImagePicker`: they stay until the controls include a popover.
- Translating "Cancel"/"OK" (`SubsetJSONPropertyEditor.java:592, 600`) and "Click to
  Add/Delete Data" (`YoungAndroidListViewAddDataPropertyEditor.java:45`).

## Steps
1. Write each model's `View` from what its editor shows and reports (e.g. choice:
   `setChoices`, `select`, `onPick`, as in the example).
2. Write the default views the way every other view is written (decision 0008): a
   `<Kind>EditorView.ui.xml` template with an `HTMLPanel` root, flex utility classes and a
   `properties-<Kind>Editor` class, whose `controls:` namespace is the contracts package
   (`client.controls`), plus behaviour-only Java that extends `SharedView`. It names no
   layout and no GWT input widget; `<controls:Select>` becomes the active layout's select through
   `SharedView`'s `@UiFactory`. Lists Java fills (choices) stay a `FlowPanel` or the control.
   Examples: `ChoiceEditorView`, `NumberEditorView`, `LengthEditorView`.
3. Make each editor build its view and talk to it through the `View` interface; keep
   validation, "commit on blur and Enter", the selected caption and the menu triangle.
4. `YoungAndroidLengthPropertyEditor`: the four radios share one group per editor
   instance, set with `Radio.setGroup` in `LengthEditorView`'s constructor. `ListViewAddDataDialog` extends `SharedView`, uses
   `<controls:Dialog>`, drops its `FocusTrap` buttons; its `Cancel` becomes a `Dialog`.
5. `ListWithNone.ListBoxWrapper` wraps a `Select` in list mode; keep the interface so
   `ListWithNoneTest`'s `FakeListBox` still works.

## Acceptance criteria
- [ ] Each model's `View` has exactly one default view in `features/properties/editors/`:
      a `.ui.xml` template plus a `SharedView` subclass, built from control interfaces only
      (no `layouts/`, no GWT input widget, no markup built in Java).
- [ ] No `new Button(`, `new TextBox(`, `new TextArea(`, `new CheckBox(`, `new ListBox(`,
      `new RadioButton(`, `new Tree(`, `new DropDownButton(`, `new TextButton(`,
      `extends DialogBox`, `<g:Button`, `<gwt:Button` or `FocusTrap` remains in either editor folder.
- [ ] Every property type edits, validates and commits as before; `ListWithNoneTest`
      passes unchanged.
- [ ] Snapshot diff shows no change in classic or neo, light or dark.

## Rules
- At most ~400 added lines and ~20 files: ship as `(1/2)` generic editors
  (`widgets/properties/`) and `(2/2)` component editors (`editor/youngandroid/properties/`).
- No visual change. `core/` gets interfaces only; views use control interfaces only.
- Short conventional commit subjects, e.g. `refactor(properties): editors draw through
  shared views`; no AI attribution.

## Summary
The two root templates become each layout's shell view:
`layouts/classic/views/shell/ClassicShell` (from `Ode.ui.xml`) and
`layouts/neo/views/shell/NeoShell` (from `style/neo/Ode.ui.xml`), both implementing
`ShellPresenter.View`. A new `core/presenters/ShellPresenter` takes the non-visual wiring
out of `Ode.initializeUi` and switches the deck between projects, editor and admin.
`UiStyleFactory.createOde` goes away and, with it, `UiStyleFactory` and `UiFactoryNeo`.
Users see no change.

## Why
- `UiStyleFactory.createOde` (`UiStyleFactory.java:22-34`) picks one of two templates with
  `style.equals("modern")`, both bound to the `Ode` entry point as owner
  (`UiBinder<FlowPanel, Ode>`). `Ode` therefore carries 17 template fields
  (`Ode.java:237-259`) for whichever template ran.
- `Ode.initializeUi` (`Ode.java:1017-1135`) mixes boot wiring (editor registry, managers,
  RPC popup, window title, history and closing handlers, drag-and-drop) with frame
  building (deck panel, CSS pick, template, tab indexes).
- The two templates are about 90% the same. Neo differs in style names, sizes
  (`width="240px"`/`"222px"` in classic vs style names in neo), the projects page flex
  column (`style/neo/Ode.ui.xml:22`), and an "Assets" caption above the asset list
  (`:34-37`).

## Out of scope
- The boxes themselves: `PaletteBox`, `ViewerBox`, `SourceStructureBox`,
  `BlockSelectorBox`, `AssetListBox`, `PropertiesBox`, `ProjectListBox`,
  `AdminUserListBox` stay shared singletons (`boxes/`, later `features/workspace/boxes`);
  the shells only place them.
- `switchToDebuggingView` (`Ode.java:543-551`): its `debuggingTabIndex = 3`
  (`:1087`) points past the deck's three pages. Keep it untouched; P0-01 or a follow-up
  decides its fate.
- Frame CSS (`ode-Root`, `ode-DeckPanel`, `ode-WorkColumns` …) moving to `views.css`
  (P6-35); the CSS bundle pick (`Ode.java:1055-1072`) is P2's.

## Steps
1. `ShellPresenter` gets the non-visual part of `initializeUi`: registering the editor
   (`:1018`), creating `FolderManager`, `ProjectManager`, `EditorManager` (`:1020-1022`),
   the RPC status popup (`:1024-1029`), window title and scrolling (`:1032-1033`), the
   expired-service overlay check (`:1035-1037`), the history handler (`:1111-1116`), the
   window-closing handler (`:1122-1127`), `HTML5DragDrop.init()` (`:1129`), the user email
   (`:1130`, through `TopBarPresenter` after P4-19) and the splash decision (`:1131-1133`). It owns `enum Page { PROJECTS,
   EDITOR, ADMIN }` and the current view constants that `switchTo…` use today.
2. `ShellPresenter.View`: `showPage(Page)`, `setDesignerBoxesVisible(boolean)`,
   `setTutorialVisible(boolean, String width)`, `setConsoleVisible(boolean)`, and getters
   for what shared code reads (`workColumns()`, `structureAndAssets()`,
   `overDeckPanel()`, `tutorialPanel()`).
3. `ClassicShell` and `NeoShell`: each a `Composite` with its own `Binder` (owner is the
   shell, not `Ode`), the context-menu-blocking `DeckPanel` (`:1041-1051`) as a provided
   field, and the slots from P4-15/16/19/20 (status bar, project toolbar, top bar, design
   toolbar) filled by the layout. Deck page order stays 0 projects, 1 editor, 2 admin.
   Drop the unused `<ui:with field="style"/>` from both templates.
4. Boot: `layout.shell()` → `new ShellPresenter(view, …)` → `RootPanel.get().add(view)`.
   Keep the pinch-zoom `RootPanel` handler (`:1094-1105`) and the dyslexic class
   (`:1107-1109`) in `Ode`, since `core` may not touch widgets.
5. Delete `UiStyleFactory`, `UiFactoryNeo`, `Ode.uiFactory` (`:296`) and the remaining
   `uiFactory` uses (`:987, 1006, 1018, 1020, 1054`).

## Rules
- Shared boxes are placed by both shells, never copied or subclassed.
- A layout never imports another layout; `ClassicShell` imports only classic views and
  shared code.
- At most ~400 added lines and ~20 files. If it does not fit, split on the ticket first:
  P4-21a `ShellPresenter` and the `Ode` wiring with both templates still owned by `Ode`
  (steps 1-2); P4-21b the two shell views and the factory deletion (steps 3-5).
- Branch `ui/p4-21-shell-views`; PR title `[new-ui P4-21] Each layout owns its page frame`;
  commits like `refactor(views): page frame per layout`; no AI attribution.

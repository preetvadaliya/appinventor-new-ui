## Summary
The design toolbar's buttons bind to `ActionId`s in both layouts, and the rules for the
Designer/Blocks switch, Add/Remove screen, the tutorial toggle, the gallery button and the
Screens menu move into a new `DesignToolbarPresenter`. Users see no change.

## Why
`DesignToolbar` mixes three things: the per-project screen model (`DesignProject`, `Screen`,
`projectMap`, `pushedScreens`), the screen switching, and button rules by name. It has seven
`WIDGET_NAME_*` constants (`editor/youngandroid/DesignToolbar.java:116-122`); four are never
used, and three of those do not match any live template:

| Constant (line) | Value | Live template name |
|---|---|---|
| `WIDGET_NAME_SWITCH_TO_BLOCKS_EDITOR` (119) | `"SwitchToBlocksEditor"` | `switchToBlocks` |
| `WIDGET_NAME_SWITCH_TO_FORM_EDITOR` (120) | `"SwitchToFormEditor"` | `switchToDesign` |
| `WIDGET_NAME_SENDTOGALLERY` (121) | `"SendToGallery"` | `Gallery` |
| `WIDGET_NAME_PROJECT_PROPERTIES_DIALOG` (122) | `"ProjectPropertiesDialog"` | same |

The first two names only exist in `YaProjectEditorClassic.ui.xml:15-18`, a template whose
binder is never created. The console button is `name="Console Toggle"` in classic
(`DesignToolbar.ui.xml:43`) and `name="ToggleConsole"` in neo (`DesignToolbarNeo.ui.xml:52`);
no code looks it up. The code that runs instead uses item names indirectly:
`setButtonEnabled(switchToBlocks.getName(), …)` (lines 397-398), `setButtonEnabled("RemoveForm", …)`
(line 402), `setButtonVisible("TutorialToggle", …)` (line 430), `setVisibleItem(…)` (lines 169,
174-175, 178) and the Screens menu by name (lines 237, 275, 282, 318, 391): 13 by-name calls. `DesignToolbarNeo` re-declares eight fields and
copies them back (`style/neo/DesignToolbarNeo.java:39-46`).

## Steps
1. Register the actions and switch both templates to `action="…"`, dropping every `name`
   (also `ScreensDropdown`); keep captions, tooltips, icons and styles. The neo "Screens: " label item stays as it is.
2. Presenter state: editor shown (designer or blocks), current screen, read-only,
   multi-screen allowed, one-project mode, tutorial available.
3. Rules on the actions: `SWITCH_TO_BLOCKS` enabled in the designer, `SWITCH_TO_DESIGNER` in
   blocks; `REMOVE_SCREEN` enabled when the current screen is not Screen1; `ADD_SCREEN` and
   `REMOVE_SCREEN` hidden for read-only accounts or without multi-screen apps;
   `SEND_TO_GALLERY` visible when the gallery is on and not read-only; `TOGGLE_TUTORIAL`
   visible when a tutorial URL is allowed (replaces `setTutorialToggleVisible`).
4. The back arrow (`SWITCH_TO_PROJECTS`) hides at its placement in one-project mode, not on
   the action: classic's File menu keeps My projects. `View.showBackArrow(boolean)`; classic
   ignores it.
5. Screens menu: the presenter passes the list and the current screen
   (`View.showScreens(List<String>, String current)`, `View.showCurrentScreen(String)`, the
   names P4-20 keeps); the view builds the `SwitchScreenAction` items and removes one by
   reference. Today `removeItem()` matches
   the item text after stripping leading whitespace (`widgets/DropDownButton.java:378-389`),
   while screen items start with an image and `&nbsp;` (lines 341-343).
6. The Ctrl+Alt shortcut (`toggleView()`, lines 405-419) runs `SWITCH_TO_BLOCKS` or
   `SWITCH_TO_DESIGNER` from the registry.
7. `DesignToolbarNeo` implements the view methods with its own fields; delete the copying.

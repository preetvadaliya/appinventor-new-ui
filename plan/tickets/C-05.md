## Summary
Decide what `controls/standard/StandardControls` is once classic and neo have their own
controls: a permanent starter set that a new layout (nova) extends piece by piece, or a
bridge that P7 deletes. Record the answer in `docs/decisions/0013-standard-controls.md`.
No code changes.

## Why
- P5-23 and P5-25 add `StandardControls`, which wraps today's widgets (`TextButton`,
  `DropDownButton`, `LabeledTextBox` …) so nothing changes on screen while views move to
  control contracts.
- After P5-26 and P5-27, classic and neo return their own pieces, but some still delegate
  to `Standard*` for behaviour (`NeoTree extends StandardTree`, P5-27), and
  `docs/06-controls.md` says a new layout "starts by extending `StandardControls`".
- If it stays, it must keep compiling and stay tested; if it goes, P7 must move or delete
  the old widgets it wraps and every layout must supply every piece.

## In scope
- Two options, with a recommendation, posted on this issue:
  1. Keep: `StandardControls` is the documented starter set; layouts may delegate to it
     for behaviour, never copy its markup.
  2. Drop: each layout supplies every control; P7 deletes `controls/standard/` and the
     wrapped widgets that nothing else uses.
- `docs/decisions/0013-standard-controls.md`
- Matching edits to `docs/06-controls.md`, P5-27, P7-39 and C-03

## Out of scope
- Writing or deleting any control
- Nova's own controls (C-03)

## Summary
A script in `misc/ui-snapshots/` signs in to a local dev server, takes PNG screenshots of 8
screens in classic and neo, light and dark (32 images), and compares two runs pixel by pixel.
Every later PR attaches its diff to prove "no visual change". Nothing in the app changes.

## Why
Most tickets in this plan promise no visual change, and reviewers at MIT cannot click through
4 combinations by hand for every PR. The repo has no browser automation today: `package.json`
only lists `karma`, `karma-firefox-launcher`, `karma-mocha`, `mocha` and `chai`, and the
checked-in `node_modules/` has no puppeteer, playwright, `ws` or PNG library. So the script
talks to Chrome over the DevTools protocol directly, using Node's built-in `WebSocket` and
`fetch` (Node 22 or later), and adds no npm dependency.

## Steps
1. Launch Chrome (path from `$CHROME`, else the usual macOS and Linux locations) with
   `--headless=new --remote-debugging-port=0 --user-data-dir=<temp dir>`; read the port from
   `<temp dir>/DevToolsActivePort`. Fix the viewport with
   `Emulation.setDeviceMetricsOverride` at 1440x900, device scale factor 1.
2. Sign in: open `http://localhost:8888/` (base URL from `--base`), follow the dev login to
   `/_ah/login`, fill the email field with `test@example.com`, submit. If the server redirects
   to `Ya_tos_form.html` (first login, `Ode.java:875`), accept it.
3. If the project list has no `UiSnapshot`, upload the fixture from inside the page with
   `fetch('/ode/upload/project/UiSnapshot', {method: 'POST', body: formData})`, the form field
   named `uploadProjectArchive` (`ServerLayout.java:137,143,189`,
   `ProjectUploadWizard.java:59,105`).
4. For each layout and theme open `/?locale=en&ui=<layout>-<theme>`. `Ode.getUserNewLayout()`
   (`Ode.java:1479-1492`) treats `ui` as a substring match: it contains `classic` -> classic,
   else contains `neo` -> neo. `Ode.getUserDarkThemeEnabled()` (`Ode.java:1437-1451`): contains
   `light` -> light, else contains `dark` -> dark. So `classic-light`, `classic-dark`,
   `neo-light`, `neo-dark`.
5. Capture these screens (driving the UI by visible English text or `title`, per layout):
   1. `projects`: the project list
   2. `trash`: the trash view (classic: "View Trash" button; neo: the icon button whose
      tooltip is "View Trash", `ProjectToolbarNeo.ui.xml:63`)
   3. `designer`: `UiSnapshot` open on Screen1
   4. `blocks`: the blocks editor for Screen1
   5. `properties`: Button1 selected, clipped to the properties box
   6. `new-project`: the "Create new App Inventor project" dialog, opened with the
      "New project" toolbar button
   7. `appearance`: Settings > "User Interface Settings" (`UISettingsWizard`)
   8. `readonly` (optional): sign in with "Sign in as Administrator", switch to the test user
      through Admin > User Admin > "Switch to This User" (`AdminUserList.java:426-432`),
      capture the project list; skip with a warning if it fails
6. Before each capture: wait for no pending network requests for 500 ms, add a stylesheet that
   turns off animations, transitions and the caret, hide the elements listed per screen as
   unstable (project dates, the RPC "Saving..." popup), and close one-time popups (splash or
   welcome dialog, `Ode.java:1131`; neo welcome tip, `Ode.java:1786`).
7. Save to `out/<label>/<layout>-<theme>-<screen>.png`.
8. `snap.mjs diff <labelA> <labelB>`: in the same headless Chrome, draw both PNGs on canvases,
   compare `getImageData`, write a diff image (changed pixels in red) and
   `out/diff-<A>-<B>/index.html` (before, after, diff side by side), print a table of changed
   pixels per image, and exit with 1 if any image differs by more than `--threshold` pixels
   (default 0).
9. README: prerequisites (Node 22+, Chrome, a running dev server), the two-run workflow
   (build master, `--label master`; build the branch, `--label branch`; `diff master branch`),
   and how to attach the result to a PR.

## Acceptance criteria
- [ ] `node misc/ui-snapshots/snap.mjs --label a` writes 28 PNGs, plus 4 for `readonly` when
      that flow works.
- [ ] Two runs against the same build give a diff of 0 pixels on every image.
- [ ] A one-line colour change in `war/static/css/Ya.css` is reported on the screens it
      affects and nowhere else.
- [ ] No new npm dependency; `package.json` is unchanged.
- [ ] The script never changes server data except creating `UiSnapshot` once.

## Rules
- At most ~400 added lines and ~20 files (the `.aia` fixture counts as one file).
- Nothing under `appengine/` changes; this PR has no visual change by definition.
- The test login is `test@example.com` on a local dev server only; never point the script at a

- Branch `ui/p0-02-snapshot-script`; PR title
  `[new-ui P0-02] A snapshot script shows UI changes before review`.
- Short conventional commit subjects, no AI attribution.

## How to verify
- Build and run the dev server (`ant -Dskip.ios=true noplay`, serve `appengine/build/war/` on
  port 8888), then run the script twice with different labels and diff them: 0 pixels.
- Change one colour in `Ya.css`, copy it into the served `build/war/static/css/`, hard reload,
  run again and diff: only the affected screens show red.
- Open `out/diff-*/index.html` and check every screen shows what its name says.

## Summary
`UiStyleFactory` and `UiFactoryNeo` are replaced by a `Layout` interface, implemented
separately by `ClassicLayout` and `NeoLayout`, and a `LayoutRegistry` that loads each one
behind its own `GWT.runAsync`. Boot asks the registry for the user's `LayoutId` and gets
everything layout-specific (shell template, image bundle, CSS) from the result. Users see no
change.

## Why
- `UiFactoryNeo extends UiStyleFactory` (`style/neo/UiFactoryNeo.java:16`): neo is defined as
  "classic plus overrides", which decision 0003 forbids.
- Layout-specific choices are spread over `Ode`: `handleUiPreference()` (`Ode.java:968-1012`)
  has two copy-pasted `runAsync` branches that pick the image bundle (`982-984`, `1001-1003`),
  the body class (`986`, `1005`) and the factory (`987`, `1006`); `initializeUi()` picks one of
  four `Ode.Resources` CSS bundles (`Ode.java:1055-1071`) and the template
  (`uiFactory.createOde`, `Ode.java:1073`).
- The factory travels through constructors: `FolderManager.java:35`, `ProjectFolder.java:92`,
  `ProjectFolderNeo.java:44`, `ProjectEditor.java:66,108`, `YaProjectEditor.java:218`,
  `YaFormEditor.java:97`, `ProjectListBox.java:34`.
- `Ode.style` (`Ode.java:259`, `@UiField(provided = true)`) is only declared in both templates
  (`<ui:with field="style" />`, `Ode.ui.xml:15`, `style/neo/Ode.ui.xml:15`); no template reads
  `{style.…}`.

## Steps
1. Create `Layout`, `ClassicLayout`, `NeoLayout`. Move each `UiFactoryNeo` override into
   `NeoLayout`; `ClassicLayout` keeps the defaults. `images(dark)` returns
   `GWT.create(DarkModeImages.class)` / `Images.class` (classic) or `DarkModeImagesNeo` /
   `ImagesNeo` (neo). `injectBundledCss(dark)` calls `ensureInjected()` on today's
   `styleclassic*` or `stylemodern*` method.
2. Create `ShellBinders` and make `createShell` call it.
3. Write `LayoutRegistry.load`: one `switch` case per id, each with its own `runAsync` whose
   callback is the only place that names `ClassicLayout` or `NeoLayout`.
4. Rewrite `handleUiPreference()` as: `UserPreferences.layout()` -> `LayoutRegistry.load` ->
   set `IMAGES`, add the body class (`classic` / `neo`, as today), set
   `data-layout="<id>"` and `data-theme="light|dark"` on `<html>`, call `injectBundledCss`,
   append a `<link>` to `<head>` for each `stylesheets()` path (URL:
   `GWT.getModuleBaseForStaticFiles()` + path + `?v=` + `GitBuildId.getVersion()`), wait for
   every `load` event (reject on `error`), then resolve. The list is empty until P2-05.
5. In `initializeUi()` delete the CSS pick and use `LayoutRegistry.active()` wherever
   `uiFactory` was used. Delete `Ode.style` and both `<ui:with field="style" />` lines.
6. Change every constructor and getter in Why from `UiStyleFactory` to `Layout`
   (`ProjectEditor.getUiFactory()` becomes `getLayout()`).

## Acceptance criteria
- [ ] `UiStyleFactory`, `UiFactoryNeo` and `Ode.style` no longer exist.
- [ ] `layouts/classic` and `layouts/neo` never import each other; no class extends another
      layout.
- [ ] `ClassicLayout` and `NeoLayout` are named only inside their own `runAsync` callback in
      `LayoutRegistry`.
- [ ] `build/war/ode/deferredjs/` has the same number of fragments as on master.
- [ ] `<html>` carries `data-layout` and `data-theme` after boot.
- [ ] Snapshot diff shows no change in classic or neo, light or dark.

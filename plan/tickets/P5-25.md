## Summary
The kit gets contracts for the inputs shared screens use: `TextField`, `Select`,
`Checkbox`, `Radio`, `Tree` and `Collapsible`, with standard implementations that wrap
today's widgets, and a `kit/behaviour/Validator` for text validation. No screen uses them
yet; users see no change.

## Why
- Shared screens construct GWT inputs directly. Across `client/` today: `new TextBox(` 21
  times plus 2 in `.ui.xml`, `new CheckBox(` 15 + 8, `new ListBox(` 13 + 6,
  `new RadioButton(` 7, `new Tree(` 4 + 2, and `LabeledTextBox` 12 + 6. A layout cannot
  draw its own input without touching every one of those files.
- `widgets/LabeledTextBox.java` (218 lines) is the only input wrapper: caption, optional
  `PasswordTextBox` (line 62), a `Validator` with an error label (lines 106-121) and
  `setColor` (line 181). 17 files (Java and `.ui.xml`) use it.
- `widgets/Validator.java` is a 10-line abstract class (`validate`, `getErrorMessage`)
  used by 6 files.
- `widgets/AbstractCollapsiblePanel.java` (121 lines) carries its own click and
  Enter/Space handling (lines 42-60); it is extended by
  `editor/simple/palette/CollapsiblePaletteCategoryPanel.java` and
  `widgets/properties/CollapsibleCategoryPanel.java`.
- `explorer/SourceStructureExplorer.java:99` subclasses `Tree` only to remember the last
  browser event, so selection can pass it on and the designer can read Meta/Ctrl.
- Five property editors need list-box mode (`setVisibleItemCount(10)`, for example
  `YoungAndroidAssetSelectorPropertyEditor.java:62`).

- `widgets/Validator.java`: `implements kit.behaviour.Validator` so old callers compile

## Out of scope
- Classic and neo implementations (P5-27)
- Using the inputs in dialogs (P5-28, P5-29), property editors (P5-30, P5-31), palette and
  tree (P5-32)
- Moving `widgets/Validator.java` or deleting `LabeledTextBox` (package moves are P7)

## Steps
1. `TextField` (extends `IsWidget`, `HasValue<String>`): `setCaption`, `setPlaceholder`,
   `setKind(TEXT | PASSWORD | MULTILINE)`, `setValidator`, `validate()`,
   `getErrorMessage`/`setErrorMessage`, `setFocus`, `selectAll`, `setEnabled`. Multiline
   covers `widgets/properties/TextAreaPropertyEditor.java`.
2. `Select`: `addItem(text, value)`, `clear`, `getSelectedValue`, `setSelectedValue`,
   `setVisibleItemCount`, `addChangeHandler`, `setEnabled`.
3. `Checkbox` (`HasValue<Boolean>`, `setText`, `setEnabled`) and `Radio` (same, plus a
   group name taken by the factory: `@UiFactory Radio radio(String name)`).
4. `Tree`: `addItem(IsWidget or SafeHtml)` returning a `Tree.Node` (add child, set open,
   get user object), `getSelected`, `setSelected`, and a selection handler whose event
   carries the triggering `NativeEvent` (replaces `EventCaptureTree.lastEvent`; the
   designer reads Meta/Ctrl from it, `MockDesignerRoot.java:208-210`).
5. `Collapsible`: `setTitle`, `addToContent`, `setOpen`, `isOpen`, `focus`, open-state
   handler. Keep the Enter/Space and `aria-expanded` behaviour.
6. Standard pieces subclass today's widgets so the DOM is unchanged:
   `StandardTextField extends LabeledTextBox`, `StandardSelect extends ListBox`,
   `StandardCheckbox extends CheckBox`, `StandardRadio extends RadioButton`,
   `StandardTree extends com.google.gwt.user.client.ui.Tree`,
   `StandardCollapsible extends AbstractCollapsiblePanel`. Add the multiline kind to
   `StandardTextField` by swapping in a `TextArea`.

## Acceptance criteria
- [ ] Six input contracts in `kit/`, six standard classes in `kit/standard/`, and
      `kit/behaviour/Validator`; `kit/` imports nothing from `layouts/` or `features/`.
- [ ] `Ui.kit()` returns each piece; a scratch `KitView` subclass with a `.ui.xml` using
      `<k:TextField>`, `<k:Select>`, `<k:Checkbox>`, `<k:Radio name="x">`, `<k:Tree>` and
      `<k:Collapsible>` compiles (do not commit the scratch view).
- [ ] `StandardTextField` with a `Validator` shows the same error label as
      `LabeledTextBox` does today.
- [ ] No existing file changes behaviour; snapshot diff shows no change in classic or neo,
      light or dark.

## Rules
- At most ~400 added lines and ~20 files.
- No visual change.
- Interfaces declare every setter a template uses as an attribute.
- Short conventional commit subjects, e.g. `refactor(kit): input contracts`;
  no AI attribution.

## Summary
The designer's rules leave `Ya.css` and the two rules files. What belongs to a layout's
regions (palette, viewer, component tree, media, properties panel and rows) goes to that
layout's `views/editor.css`; what the shared property editor views need goes to the shared
`features/public/features/properties.css`; the user's app components (mocks) and the four
phone-preview skins move next to the mocks (decision 0010). Shared files read tokens only.
Classic and neo look exactly as before.

## Why
`war/static/css/Ya.css` (4,137 lines, 613 rule blocks, 468 class names) is linked on every
page (`war/index.jsp:75`). About 138 of its rules (~900 lines) style the designer:
- 904-935 component tree (`.ode-SourceStructureExplorer`, `.ode-NavArrow`), 4 rules
- 956-996 non-visible components and `.ode-Icon`, 7 rules
- 1221-1353 palette (`.ode-PaletteCategory*`, `.gwt-StackPanel*`, `.ode-SimplePaletteItem*`), 20 rules
- 1354-1399 explorer panels (`.ode-CollapsiblePanel*`, `.ode-HeaderPanel*`), 8 rules
- 1400-1598 properties panel (`.ode-Property*`, choice and colour editors), 26 rules
- 1599-1903 viewer and mocks (`.ode-SimpleFormDesigner`, `.ode-SimpleMock*`, list view,
  spinner, image), 50 rules; 1904-1943 component help popup, 6 rules
- 2772-2821 properties disclosure panels, 10 rules; 3686-3728 map markers and the file drop
  zone `div.dropdiv`, 5 rules; 3784-3793 `.listItem`, `.components-tree-filter`, 2 rules

The same classes are restyled per layout: about 85 rules in `layouts/neo/public/neo/neo.css`
and 60 in `layouts/classic/public/classic/variableColors.css` touch them. The phone skins
`android_holo.css` (4 rules), `android_material.css` (3), `iOS.css` (27) and
`DarkTheme.css` (7) style the user's app (`MockForm.java:657-667` adds
`AndroidMaterial`/`AndroidHolo`/`iOS`), not the IDE, yet sit in `war/static/css` and are
linked globally (`index.jsp:76-79`).

## Steps
1. Add `<public path="client/features/designer/mocks/public"/>` to `YaClient.gwt.xml`, so
   the skins are served at `ode/mocks/` (`client/features/public` is served since P4-15).
2. Link `ode/features/properties.css` in `index.jsp` after `layout.css`, and point lines
   76-79 at `<%= odeBase %>ode/mocks/…` plus `mocks.css`. Each layout lists
   `views/editor.css` last in `stylesheets()`.
3. Move the skins. Fix their `url()`s: `iOS.css` has 7 (`../fonts/Helvetica.ttf`,
   `../images/iPhoneX*.png` …) that must become `../../static/…`.
4. For each class in scope, collect its rules from `Ya.css`, `variableColors.css` and
   `neo.css`. Region rules go into both layouts' `views/editor.css`, each merged with that
   layout's override (no shared region file); shared-part rules go to `properties.css`,
   `dialogs.css` or `mocks.css` with `var(--token)` colours. Delete the originals.
5. Rewrite the 8 `url(../images/…)` in this range (phone frames 1645-1677, navigation bars
   1739-1747) to `../../static/images/…`.
6. Update the comments that point at `Ya.css` in `MockWrapper.java:17`,
   `MockComponent.java:107`, `MockAbsoluteArrangement.java:127`, `MockHVArrangement.java:198`.

## Acceptance criteria
- [ ] `Ya.css` and both rules files have no rule for any class listed above.
- [ ] `properties.css`, `dialogs.css` and `mocks.css` contain no hex colour and no GWT
      syntax (`@def`, bare token names); neither `views/editor.css` names the other layout.
- [ ] `ode/features/properties.css`, `ode/mocks/*.css` and each layout's
      `views/editor.css` load (HTTP 200); classic never loads neo's file and the reverse.
- [ ] Phone sizes, Material/Holo/iOS previews and the phone dark theme look as before.
- [ ] Snapshot diff shows no change in classic or neo, light or dark.

## Rules
- At most ~400 new lines and ~20 files. Rules moved verbatim are reviewed with
  `git diff --color-moved` and do not count, but the second copy of each region rule does;
  if the PR still grows past the limit, open `(1/2)` palette/tree/properties and `(2/2)`
  viewer/mocks/skins.
- No visual change. Watch cascade ties: a rule that moves later in the load order can win
  where it used to lose; fix by keeping specificity, not with `!important`.
- Short conventional commit subjects, e.g. `refactor(css): designer rules leave Ya.css`;
  no AI attribution.

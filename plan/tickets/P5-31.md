## Summary
The logic of every property editor moves into models in `core/properties/editors/`
(`ChoiceEditorModel`, `TextEditorModel`, `NumberEditorModel`, `ColorEditorModel`,
`AssetEditorModel` …), each driving the shared default view from P5-30 through its `View`
interface. The 36 choice editors become data: option lists in eight files under
`core/properties/choices/`, with today's values and captions. `PropertyEditors.forType(type)`
picks the model for each editor type in `simple_components.json`. The old editor classes
are deleted. Classic and neo look and behave as before (decision 0011).

## Why
- 36 editors extend `ChoicePropertyEditor` only to list options: 33 in
  `editor/youngandroid/properties/` and 3 in `widgets/properties/`
  (`LanguageChoicePropertyEditor`, `CountryChoicePropertyEditor`,
  `ScalingChoicePropertyEditor`). Each is a class of 22-56 lines.
- The folder `editor/youngandroid/properties/` has 54 files: 51 Java classes,
  `package-info.java` and 2 `.ui.xml`. 48 classes are editors (47 `*PropertyEditor` plus
  `YoungAndroidDataColumnSelectorProperty`); the others are `ListViewAddDataDialog`,
  `ListViewDataRow` and `ListWithNone`.
- The type-to-editor map is one 143-line `if`/`else` chain,
  `PropertiesUtil.createPropertyEditor` (`editor/simple/components/utils/PropertiesUtil.java:216-358`).
- Value checks (number ranges, non-negative, colour, length) live in widget classes and
  cannot be unit-tested without a browser.
- Not every choice editor is a plain list: `YoungAndroidChatbotProviderPropertyEditor` (98
  lines) and `YoungAndroidChatbotModelPropertyEditor` (130 lines) fetch their options from
  the chat proxy (`onResponseReceived`, lines 57 and 67); `YoungAndroidMinSdkPropertyEditor`
  builds its list in code (`buildChoices`, line 18).

## In scope
- New `core/properties/choices/Choice.java`, `Choices.java` and the eight lists:
  `LayoutChoices` (horizontal, vertical and text alignment, button shape, sizing, stroke
  style, list view layout, recycler view orientation), `ScreenChoices` (animation,
  orientation, theme, min SDK, scaling, toast length, file scope), `SensorChoices`
  (accelerometer sensitivity, distance and time interval, text receiving), `LegoChoices`
  (5), `ChartChoices` (type, line type, point shape, label value type, best-fit model),
  `MapChoices` (map type, scale units, navigation method), `ChatbotChoices` (provider,
  model), `LocaleChoices` (language, country). 36 lists in all.
- New `core/properties/editors/PropertyEditor.java` and the model logic in each
  `<Kind>EditorModel` whose `View` P5-30 declared; `PropertyEditors.java` (`forType`).
- `PropertiesUtil.createPropertyEditor` and its callers (`PropertiesUtil.java:141`,
  `MockComponent.java:394, 402`, `MockForm`, `MockHVArrangement`) use `PropertyEditors`.
- Delete the 36 choice editors, `ChoicePropertyEditor` and every other old editor whose
  model and view now exist.
- Unit tests: `appengine/tests/…/client/core/properties/` for `Choices` and the models.

## Out of scope
- The default views (P5-30); the properties panel and rows (P5-43).
- Changing any option, value, caption or order.
- Moving `widgets/properties/PropertiesPanel`, `EditableProperty`, `EditableProperties`
  (P7-39).

## Steps
1. Copy each list's values and captions into its `Choices` constant, in today's order,
   with a `/** Was <EditorClass>. */` line. Keep the `MESSAGES` captions as calls.
2. Chatbot provider and model: `ChatbotChoices` holds the built-in fallback; the model asks
   a small loader (outside `core/`, since it does HTTP) for the proxy's list, as today.
   Min SDK keeps its computed list as a method on `ScreenChoices`.
3. Move value checks into the models (`NumberEditorModel` with min, max and non-negative;
   `TextEditorModel` with its validators; `ColorEditorModel`; `LengthEditorModel` …). A
   model saves through `property.setValue` and only saves values it accepts. It reports a
   wrong value through `View.showError` and never calls `Window.alert` itself (decision
   0012).
4. `PropertyEditors.forType(type)` maps every type `createPropertyEditor` handles today;
   unknown types fall back to `TextEditorModel`, as today's `else` branch does.
5. Point the callers at `forType`; attach each model to its default view; delete the old
   classes.
6. Tests: every `Choices` list has the same values as before (compare against a list
   captured from master in the test), and each model rejects what its editor rejected.

## Acceptance criteria
- [ ] `core/properties/**` imports no GWT widget and nothing from `controls/`, `features/`
      or `layouts/`.
- [ ] No class extends `ChoicePropertyEditor`; it and the 36 choice editors are gone; the
      eight choice files hold 36 lists with unchanged values and captions.
- [ ] `PropertyEditors.forType` covers every editor type `createPropertyEditor` covered.
- [ ] Model tests pass under `ant tests`; `ListWithNoneTest` still passes.
- [ ] Projects saved before and after load the same; `.scm` output is byte-identical for a
      project that uses every choice property.
- [ ] Snapshot diff shows no change in classic or neo, light or dark.

## Rules
- At most ~400 added lines and ~20 files; deleted classes do not count. Ship as `(1/2)`
  choices (steps 1-2 and the choice part of 4-6) and `(2/2)` the other models.
- No visual change. No layout class anywhere in `core/` or `features/`.
- Short conventional commit subjects, e.g. `refactor(properties): choice lists become
  data`; no AI attribution.

## How to verify

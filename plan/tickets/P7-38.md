## Summary
Every client file whose final home in `docs/file-map.html` is a single file under `core/`
moves there with `git mv`. The PR changes package lines, imports and the few hard-coded
class names that point at the moved files, nothing else. Users see no change.

## Why
P1 to P6 put new code straight into its final package but left existing logic where it
was, so that open contributor PRs kept applying (decision 0005). The models, commands,
RPC plumbing and actions still sit in `client/`, `client/actions`, `client/explorer/…`,
`client/settings/…`. `map.json` has 150 single-target moves into `core/`.

## Steps
1. Generate the move list from `map.json` and drop entries already moved
   (`git ls-files` on the old path).
2. `git mv` each file with its `.ui.xml`, `.properties` and resources; move a
   `package-info.java` only if its package becomes empty.
3. Commit the moves alone, then a second commit with package lines and references
   (an IDE "move class" refactoring does most of it; grep for the leftovers above).

## Acceptance criteria
- [ ] Every single-target `core/` entry in `map.json` exists at its new path.
- [ ] `git grep` finds no reference to an old package of a moved class.
- [ ] No line changes besides package lines, imports, qualified names and the paths listed.
- [ ] Snapshot diff shows no change in classic or neo, light or dark.

## Rules
- Pure move PR: exempt from the ~400 lines / ~20 files limit, but no other edits.
- Merge on the day agreed in C-02, together with P7-39.
- Short conventional commit subjects, e.g. `refactor(core): move logic packages to core`;
  no AI attribution.

## How to verify
- `ant checkstyle -Dcommit=upstream/master`: no warnings on changed lines
  (`docs/13-code-style.md`)
- `ant -Dskip.ios=true noplay`, `ant tests`, `ant BlocklyTest`
- `git diff -M --stat` shows renames at 100% similarity in the first commit
- By hand: open a project, build, check RPC errors still show, change a project setting;
  run `?locale=fr_FR` to check translations load.

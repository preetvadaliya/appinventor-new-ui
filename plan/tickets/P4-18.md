## Summary
The project list, its rows and its folder rows become independent views per layout:
`ClassicProjectList`, `ClassicProjectRow`, `ClassicProjectFolder` in
`layouts/classic/views/projects/`, and `NeoProjectList`, `NeoProjectRow`, `NeoProjectFolder`
in `layouts/neo/views/projects/`. They implement the `View` contracts of
`ProjectListPresenter` (P4-17). The list is created by `Layout.projectList()`, so the
factory hooks in `UiStyleFactory`/`UiFactoryNeo` go away. Users see no change.

## Why
Each neo class subclasses its classic twin, re-declares every `@UiField` and copies it back
to the parent:
- `style/neo/ProjectListNeo.java:25-35` re-declares 11 fields, `:41-51` copies them back;
  `:58-61` re-declares the `selectAllCheckBox` handler only to call `super`.
- `style/neo/ProjectFolderNeo.java:27-34` re-declares 8 fields, `:52-59` copies them back;
  `:67-83` re-declares three handlers.
- `style/neo/ProjectListItemNeo.java:28-33` re-declares 6 fields, `:42-47` copies them back;
  `:50-65` re-declares three handlers.

The copying exists because the generated binder lives in the subclass's package
(`style.neo`) and cannot assign the parent's `protected` fields declared in
`explorer.youngandroid` / `explorer.folder`. Independent classes remove the need.

The list is created through the style factory: `UiStyleFactory.createProjectList()`
(`UiStyleFactory.java:36-38`), overridden by `UiFactoryNeo.java:18-21`, called from
`ProjectListBox.create(UiStyleFactory)` (`boxes/ProjectListBox.java:34-39`) at
`Ode.java:1054`. Rows come from `createProjectListItem` overrides
(`ProjectList.java:315-317`, `ProjectListNeo.java:63-66`, `ProjectFolder.java:220-222`,
`ProjectFolderNeo.java:62-65`).

`ProjectListNeo.bindIU()` (`ProjectListNeo.java:37-56`) also skips the ARIA setup that
classic does in `ProjectList.java:105-120` (region role, column-header labels, `aria-sort`).

## Steps
1. Templates per decision 0008: root `<gwt:HTMLPanel>`; the header row is a flex `<gwt:HTMLPanel>`
   holding the select-all checkbox and one `FocusPanel` per sortable column; the rows are
   one `<gwt:FlowPanel ui:field="rows">` (Java adds them) marked `overflow-auto`; a row is a
   `FocusPanel` around a `flex-row items-center` `HTMLPanel`; a folder adds a `FlowPanel` for its children.
   Today's `FlowPanel` nesting becomes flex `HTMLPanel`s and its text `Label`s; today's style names stay next to the flex
   classes (`ode-ProjectRow`, `ode-ProjectListDate` …) so `Ya.css` still applies.
2. Each list view is a `Composite` with its own `Binder` that implements
   `ProjectListPresenter.View`. It builds rows with its own row and folder classes
   (`new ClassicProjectRow(project, presenter)` …); no factory method, no override.
3. Rows and folder rows keep today's style names and behaviour: nested `childrenContainer`,
   `ode-ProjectRowHidden` for collapsed folders, the `expand_more`/`chevron_right` icon swap
   (`ProjectFolder.java:158, 163`), and the drag-to-desktop export URL and native
   `configureDraggable` (`ProjectListItem.java:50-54, 120-127`).
4. Put the ARIA setup from `ProjectList.java:105-120` and `updateSortAriaAttributes`
   (`209-233`) in both list views, so neo gets it too.
5. `ClassicLayout.projectList()` returns `new ClassicProjectList()`, `NeoLayout` returns
   `new NeoProjectList()`. `ProjectListBox` takes the view from the layout and the presenter
   is created with it.
6. Delete `createProjectList` from both factories and the 12 old files.

## Acceptance criteria
- [ ] Six new view classes, each with its own `.ui.xml` whose root is a `<gwt:HTMLPanel>`
      and whose only `FlowPanel`s are the lists Java fills; no class in
      `layouts/neo/views/projects` extends one in `layouts/classic` or the reverse.
- [ ] No re-declared `@UiField`s, no `super.x = x`, no handler re-declared just to call
      `super`.
- [ ] `UiStyleFactory` and `UiFactoryNeo` have no project-list or folder hooks left.
- [ ] Neo's list has `role="region"`, the column-header `aria-label`s and `aria-sort`, as
      classic does (the only intended difference; it is not visible).
- [ ] Dragging a project row to the desktop still downloads its `.aia` (Chrome).
- [ ] Snapshot diff shows no change in classic or neo, light or dark.

## Rules
- Views only draw and report clicks; they never sort, count or decide.
- Templates follow decision 0008: every box a flex `HTMLPanel`, no raw `<div>`/`<span>`, `FlowPanel` only for lists,
  `addStyleNames` on components; one small template per repeated item (row, folder).
- A layout never imports another layout.
- At most ~400 added lines and ~20 files. Move each template with `git mv` first so the
  history follows it; Java per view about 40-80 lines. If it runs over, split by layout: classic views
  first, neo second.
- Branch `ui/p4-18-project-list-views`; PR title `[new-ui P4-18] Each layout has its own
  project list views`; commits like `refactor(views): project list per layout`; no AI
  attribution.

## Summary
Both the light and the dark image bundle of the active layout are loaded at boot, and every
image whose light and dark versions differ is shown through a `ThemedImage` that swaps when a
`ThemeChangedEvent` fires. `core/theme` gets `ThemeMode`, `ThemeChangedEvent` and a first
`ThemeService` that holds the current theme and fires the event. Nothing fires it yet in the
UI (P2-08 does), so users see no change.

## Why
- One bundle is picked once at boot: `IMAGES = GWT.create(DarkModeImagesNeo / ImagesNeo /
  DarkModeImages / Images)` (`Ode.java:982-1003`, after P1-04 `Layout.images(dark)`), returned
  by `Ode.getImageBundle()` (`Ode.java:361`).
- Dark only changes some images. `Images` has 137 methods; `DarkModeImages` replaces 9
  (palette icons such as `barometer`, `listview`, `translator`); `DarkModeImagesNeo` replaces
  93 (90 marked `@Override`): component icons, `marker`, `GetApp`, the five `mediaIcon*`.
- `Ode.getImageBundle()` is called 20 times in 16 files; with the 5 `GWT.create` calls
  (`Ode.java` x4, `explorer/youngandroid/GalleryImages.java:16`) that is 25 sites in 17
  files. Several cache the bundle in a static field at class load: `BlocksEditor.java:60`,
  `MockComponent.java:311`, `BlockSelectorBox.java:106`, `ComponentHelpWidget.java:31`,
  `ComponentRemoveWidget.java:22`, and the path-to-image map in
  `YoungAndroidComponentFactory.java:22-25`.
- Some icons are copied into HTML strings and can never swap in place: the component tree
  (`MockComponent.java:864`), the "Any component" drawer (`MockComponent.java:905`, read by
  `BlockSelectorBox.java:241`) and the asset list (`AssetList.java:148-156`).

## In scope
- New `core/theme/ThemeMode.java` (`LIGHT`, `DARK`, `SYSTEM`), `core/theme/ThemeChangedEvent.java`
  (a `GwtEvent` carrying `isDark()`), `core/theme/ThemeService.java` (`get()`, `isDark()`,
  `addThemeChangedHandler()`, `apply(boolean dark)` which updates the state and fires; set at
  boot from `Ode.getUserDarkThemeEnabled()`)
- New `kit/ThemedImage.java`: an `Image` built from any bundle's `ImageResource`; while
  attached it listens for the event and shows the same-named resource from the matching bundle
- `Images.java`: also extend `ClientBundleWithLookup`, so a resource can be found by
  `ImageResource.getName()` in the other bundle (inherited by the three other bundles)
- `Ode.java`: keep a light and a dark bundle (`layout.images(false)`, `layout.images(true)`);
  `getImageBundle()` returns the current one; add `getImageBundle(boolean dark)`
- Switch to `ThemedImage`: `editor/simple/palette/BaseComponentFactory.java:258` (palette,
  non-visible components, tree icons), `editor/simple/components/MockVisibleComponent.java:112`,
  `editor/simple/components/MockMarker.java:47`, `wizards/MarkOriginWizard.java:140`,
  `explorer/commands/ShowBarcodeCommand.java:164`
- Rebuild on the event: `explorer/youngandroid/AssetList.java` (its tree), and the open
  editor's component tree (`SourceStructureBox.show(root)`, `SourceStructureBox.java:65`;
  `BlocksEditor.updateBlocksTree`, `BlocksEditor.java:684`)

## Out of scope
- Firing the event from the appearance dialog, `data-theme`, saving, Blockly, charts (P2-08)
- Icon sets keyed by `IconKey` and Material Symbols (P4-22)
- Images that are the same in light and dark (box buttons, block categories, `form`, the
  phone bars in `MockForm`, `GalleryImages`): leave them as they are

## Steps
1. Add the three `core/theme` classes. `ThemeService` imports no widget classes.
2. Make `Images` extend `ClientBundleWithLookup`; load both bundles in the layout callback.
   Record the size of the layout's `deferredjs` fragment before and after in the PR.
3. Write `ThemedImage`: register the handler in `onLoad()`, remove it in `onUnload()`, and
   re-sync in `onLoad()` in case the theme changed while it was detached. Keep `alt` text and
   size when swapping.
4. Replace `new Image(res)` with `new ThemedImage(res)` at the listed sites.
5. For the HTML-string copies, rebuild the asset list and the active component tree when the
   event fires.
6. For local testing only (do not commit), expose `ThemeService.get().apply(!isDark())` to the
   console through a JSNI `$wnd` function.

## Acceptance criteria
- [ ] Booting in light or dark shows exactly the images it shows on master.
- [ ] With the local test hook, toggling swaps every image that differs, with no reload:
      classic's 9 palette icons; in neo also tree and non-visible component icons, the map
      marker, the barcode dialog icon and the asset icons.
- [ ] `ThemedImage` holds no handler after it is detached (no leak when switching screens).
- [ ] `core/theme` imports nothing from `com.google.gwt.user.client.ui`.
- [ ] Snapshot diff shows no change in classic or neo, light or dark.

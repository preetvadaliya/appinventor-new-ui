## Summary
Every client file whose final home in `docs/file-map.html` is a single file under
`features/` moves there with `git mv`, together with the few pure moves into
`controls/behaviour/`. The PR changes package lines, imports and hard-coded class names that
point at the moved files, nothing else. Users see no change.

## Why
The shared screens (designer and its 103 `Mock*` files, palette, properties and editors,
blocks, dialogs, panes) still live in the old `editor/`, `explorer/`, `widgets/`,
`wizards/` and `boxes/` packages. `map.json` has 309 single-target client moves into
`features/` (plus the 4 skins P6-33 already moved).

## Steps
1. Generate the list from `map.json`, drop entries already moved, add the non-Java files
   named above and each moved package's `package-info.java` if the package empties.
2. Commit the `git mv`s alone; then one commit for package lines and references; then
   one commit for the renames.

## Acceptance criteria
- [ ] Every single-target `features/` entry in `map.json` exists at its new path.
- [ ] `git grep` finds no reference to an old package or old class name.
- [ ] No line changes besides package lines, imports, qualified names, renames and the
      paths listed.
- [ ] Component translations still load (generated sources compile into the new package).
- [ ] Snapshot diff shows no change in classic or neo, light or dark.

## Rules
- Pure move PR: exempt from the ~400 lines / ~20 files limit, but no other edits.
- Merge on the day agreed in C-02, right after P7-38.
- Short conventional commit subjects, e.g. `refactor(features): move shared screens`;
  no AI attribution.

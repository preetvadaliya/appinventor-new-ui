## Summary
The project toolbar becomes two independent views, `layouts/classic/views/projects/ClassicProjectToolbar`
and `layouts/neo/views/projects/NeoProjectToolbar`, each implementing
`ProjectToolbarPresenter.View` (from P3-10) with its own template. `ProjectToolbarNeo` no
longer extends `ProjectToolbar`; the active `Layout` hands the view to the frame. Users see
no change.

## Why
`style/neo/ProjectToolbarNeo.java` (30 lines) extends `explorer/youngandroid/ProjectToolbar.java`
only to bind its own template: it re-declares `projectLabel` and `trashLabel`
(`ProjectToolbarNeo.java:22-23`, hiding `ProjectToolbar.java:41-42`) and copies them back
in its `bindProjectToolbar()` override (`ProjectToolbarNeo.java:25-29`). After P3-10 the
enable/visible rules already live in `ProjectToolbarPresenter`, so what is left in
`ProjectToolbar` is rendering, and the subclass exists only to swap markup. Both frames
name the concrete class: `Ode.ui.xml:22` (`<ex:ProjectToolbar>`) and
`style/neo/Ode.ui.xml:23` (`<neo:ProjectToolbarNeo>`), bound to `Ode.java:249`
(`@UiField protected ProjectToolbar projectToolbar`).

## Steps
1. `ClassicProjectToolbar extends Composite implements ProjectToolbarPresenter.View`, with
   `interface Binder extends UiBinder<Widget, ClassicProjectToolbar>`. Template per
   decision 0008: a `<g:HTMLPanel styleName="flex-row items-center">` root holding the title labels
   and today's `<ai:Toolbar addStyleNames="grow">` with its `ToolbarItem`s and the P3-10
   action ids (a `ToolbarItem` only works inside a `Toolbar`). Implement the `View`
   methods (`showTitle(String)` and `showTrash(boolean)` from P3-10; together they show the "Projects" or "Trash"
   label that `setProjectTabButtonsVisible`/`setTrashTabButtonsVisible` used to toggle).
2. `NeoProjectToolbar` the same way from `ProjectToolbarNeo.ui.xml`. Keep its
   `ya-ProjectToolbar` class (as `addStyleNames` on the `Toolbar`), the `icon=` attributes, the neo-only `ImportProject`,
   `ImportTemplate` and `Export` items, and the `align` groups exactly as they are. It
   must not extend `ClassicProjectToolbar`.
3. `ClassicLayout.projectToolbar()` returns `new ClassicProjectToolbar()`;
   `NeoLayout.projectToolbar()` returns `new NeoProjectToolbar()`.
4. In `Ode`, follow the P4-15 pattern: `@UiField(provided = true) protected Widget
   projectToolbar`, filled from `layout.projectToolbar().asWidget()` before the frame is
   bound, with `<g:Widget ui:field="projectToolbar" width="100%"/>` (classic) and
   `<g:Widget ui:field="projectToolbar"/>` (neo) in the templates. Create
   `ProjectToolbarPresenter` with the same view instance.
5. Remove `getProjectToolbar()` if P3-10 left no callers; otherwise make it return the
   presenter. Delete the four old files.

## Acceptance criteria
- [ ] `ClassicProjectToolbar` and `NeoProjectToolbar` each have their own `.ui.xml` with a
      `<g:HTMLPanel>` root, both implement `ProjectToolbarPresenter.View`, and neither
      extends the other or `widgets/Toolbar`.
- [ ] No `super.x = x` copies and no re-declared `@UiField`s remain for the project toolbar.
- [ ] `Ode.java` names neither concrete toolbar class.
- [ ] Projects view: New, Folder, Move, Delete, Trash and (with the gallery on) Login/Send
      to Gallery show; Trash view: Restore, Projects, Delete From Trash show; neo also
      shows Import project, Import template and Export.
- [ ] Read-only accounts cannot create, delete or restore projects.
- [ ] Snapshot diff shows no change in classic or neo, light or dark.

## Rules
- A view only renders and reports clicks; rules stay in `ProjectToolbarPresenter`.
- Templates follow decision 0008 (every box an `HTMLPanel`, text as `Label`/`InlineLabel`, no raw
  `<div>`/`<span>`, `addStyleNames` on components); today's style names stay until P6-35.
- `layouts/classic` never imports `layouts/neo` and the reverse.
- At most ~400 added lines and ~20 files; move the templates with `git mv` so they show as
  renames. No visual change.
- Branch `ui/p4-16-project-toolbar-views`; PR title `[new-ui P4-16] Each layout has its
  own project toolbar view`; commits like `refactor(views): project toolbar per layout`;
  no AI attribution.

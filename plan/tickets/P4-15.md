## Summary
The footer becomes two independent views, `layouts/classic/views/status/ClassicStatusBar`
and `layouts/neo/views/status/NeoStatusBar`, each with its own UiBinder template and no
inheritance between them. The active `Layout` supplies the view to the page frame. Users
see no change. This is the smallest view ticket and sets the pattern P4-16 to P4-21 follow.

## Why
`StatusPanelNeo` (`style/neo/StatusPanelNeo.java`, 28 lines) extends `StatusPanel`
(`StatusPanel.java`, 56 lines) only to bind a different template. It re-declares the
parent's `@UiField`s (`StatusPanelNeo.java:18-19`) and copies one back with
`super.tosLink = tosLink` (`StatusPanelNeo.java:26`). The two templates,
`StatusPanel.ui.xml` and `style/neo/StatusPanelNeo.ui.xml`, are byte-identical (13 lines
each). The view also reaches into `Ode.getSystemConfig()` for the terms-of-service URL
(`StatusPanel.java:38-43`) instead of being handed it.

## Steps
1. Create `ClassicStatusBar`: a `Composite` with its own
   `interface Binder extends UiBinder<FlowPanel, ClassicStatusBar>`, fields
   `footer` (provided, `new FlowPanel("footer")` so the root stays a `<footer>` element) and
   `tosLink`, and a constructor `ClassicStatusBar(String tosUrl)` that sets the href or
   removes the link when the URL is empty. Copy `StatusPanel.ui.xml` unchanged as its
   template (class `ode-StatusPanel`, message `privacyTermsLink`).
2. Create `NeoStatusBar` the same way with its own copy of the template. It must not
   extend `ClassicStatusBar` or share a base class with it.
3. Add `Widget statusBar(String tosUrl)` to `Layout`; `ClassicLayout` returns
   `new ClassicStatusBar(tosUrl)`, `NeoLayout` returns `new NeoStatusBar(tosUrl)`.
4. In `Ode`, make the field `@UiField(provided = true) protected Widget statusPanel` and
   assign it from the active layout with `getSystemConfig().getTosUrl()` before the frame
   is bound. In both `Ode.ui.xml` files replace the old element with
   `<g:Widget ui:field="statusPanel" />` (if the UiBinder generator rejects that element,
   use a `<g:SimplePanel ui:field="statusSlot"/>` and `setWidget` the layout's view).
5. Delete the four old files and the `ode:`/`neo:` imports that only served them.

## Acceptance criteria
- [ ] `ClassicStatusBar` and `NeoStatusBar` exist, each with its own `.ui.xml`, and neither
      extends the other or any shared status-bar class.
- [ ] Neither view calls `Ode`; the TOS URL arrives through the constructor.
- [ ] No class named `StatusPanel*` remains; `Ode.java` names no concrete status view.
- [ ] With a TOS URL configured the "Privacy Policy and Terms of Use" link opens it in a new
      tab; with none, the link is absent (unchanged behaviour).
- [ ] Snapshot diff shows no change in classic or neo, light or dark.

## Rules
- Pattern for every later view ticket: one independent class per layout, its own
  UiBinder, data passed in (or a presenter `View` interface), created by a `Layout` method.
- No layout class imports another layout's package (`layouts/classic` never sees
  `layouts/neo`).
- At most ~400 added lines and ~20 files. No visual change.
- Branch `ui/p4-15-status-bar`; PR title `[new-ui P4-15] Each layout has its own status bar
  view`; short conventional commits such as `refactor(views): status bar per layout`; no AI
  attribution.

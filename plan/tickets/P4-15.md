## Summary
The footer becomes two independent views, `layouts/classic/views/status/ClassicStatusBar`
and `layouts/neo/views/status/NeoStatusBar`, each with its own UiBinder template and no
inheritance between them. The active `Layout` supplies the view to the page frame. The
shared `features/public/features/reset.css` and `layout.css` (decision 0010) arrive here,
because this is the first template written with the flex classes. Users see no change.
This is the smallest view ticket and sets the pattern P4-16 to P4-21 follow.

## Why
`StatusPanelNeo` (`style/neo/StatusPanelNeo.java`, 28 lines) extends `StatusPanel`
(`StatusPanel.java`, 56 lines) only to bind a different template. It re-declares the
parent's `@UiField`s (`StatusPanelNeo.java:18-19`) and copies one back with
`super.tosLink = tosLink` (`StatusPanelNeo.java:26`). The two templates,
`StatusPanel.ui.xml` and `style/neo/StatusPanelNeo.ui.xml`, are byte-identical (13 lines
each). The view also reaches into `Ode.getSystemConfig()` for the terms-of-service URL
(`StatusPanel.java:38-43`) instead of being handed it.

## Steps
1. Create `ClassicStatusBar`: a `Composite` with its own `Binder` and a constructor
   `ClassicStatusBar(String tosUrl)` that sets the href or removes the link when the URL is
   empty. Template per decision 0008: `<g:HTMLPanel tag="footer" styleName="flex-row items-center
   justify-end ode-StatusPanel">` (the `tag` keeps today's `<footer>` element) with the
   `<g:Anchor ui:field="tosLink" text="{messages.privacyTermsLink}" target="_blank"/>`.
   Keep `ode-StatusPanel` next to the flex classes so today's CSS still applies.
2. Create `NeoStatusBar` the same way with its own copy of the template. It must not
   extend `ClassicStatusBar` or share a base class with it.
3. Add `Widget statusBar(String tosUrl)` to `Layout`; `ClassicLayout` returns
   `new ClassicStatusBar(tosUrl)`, `NeoLayout` returns `new NeoStatusBar(tosUrl)`.
4. In `Ode`, make the field `@UiField(provided = true) protected Widget statusPanel`, assign
   it from the active layout with `getSystemConfig().getTosUrl()` before the frame is
   bound, and use `<g:Widget ui:field="statusPanel" />` in both `Ode.ui.xml` (if UiBinder
   rejects it, a `<g:SimplePanel ui:field="statusSlot"/>` filled with `setWidget`).
5. Add the two CSS files. `layout.css` is the example as written. `reset.css` holds only
   rules that match today's page (`html, body { margin: 0 }`, `[hidden]`); the
   `overflow: hidden` on `html, body` comes with the full-height shell (P4-21), the body
   font, background and `box-sizing` with the page globals (P6-35).
6. Delete the four old files and the `ode:`/`neo:` imports that only served them.

## Acceptance criteria
- [ ] `ClassicStatusBar` and `NeoStatusBar` exist, each with its own `.ui.xml` whose root
      is a `<g:HTMLPanel>`; neither extends the other or any shared status-bar class.
- [ ] Neither view calls `Ode`; the TOS URL arrives through the constructor.
- [ ] No class named `StatusPanel*` remains; `Ode.java` names no concrete status view.
- [ ] `ode/features/reset.css` and `ode/features/layout.css` load (HTTP 200) after
      `Ya.css`; `layout.css` has no colour, font, border or size.
- [ ] The `.center` utility does not move today's toolbars: `widgets/Toolbar.java:49` sets
      class `center` on its middle group (`Ya.css:3744`, `neo.css:414, 1949`); the
      snapshot diff of every toolbar is clean.
- [ ] With a TOS URL the "Privacy Policy and Terms of Use" link opens it in a new tab;
      with none, the link is absent (unchanged).
- [ ] Snapshot diff shows no change in classic or neo, light or dark.

## Rules
- Pattern for every later view ticket: one independent class per layout, its own
  template, data passed in (or a presenter `View` interface), created by a `Layout` method.
- Templates follow decision 0008: every box an `<g:HTMLPanel>` with flex classes, text as `Label`/`InlineLabel`, no raw `<div>`/`<span>`,
  `FlowPanel` only for lists Java fills, `SimplePanel` only for one slot, `addStyleNames`
  (never `styleName`) on a component; today's style names stay until P6.
- No layout class imports another layout's package. At most ~400 added lines and ~20
  files. No visual change.
- Branch `ui/p4-15-status-bar`; PR title `[new-ui P4-15] Each layout has its own status bar
  view`; commits like `refactor(views): status bar per layout`; no AI attribution.

## Summary
The top bar and the main menu become independent views per layout:
`layouts/classic/views/topbar/ClassicTopBar` and `layouts/classic/views/menus/ClassicMainMenu`
(all six menus in one template), `layouts/neo/views/topbar/NeoTopBar` and
`layouts/neo/views/menus/NeoMainMenu`. The menus render the action ids from P3-11/P3-12 and take
their rules from `MainMenuPresenter`; the account, language and logo logic in `TopPanel`
moves to a new `core/presenters/TopBarPresenter`. Users see no change, except one neo bug
fix noted below.

## Why
- `style/neo/TopPanelNeo.java` (56 lines) extends `TopPanel.java` (187 lines), re-declares
  10 `@UiField`s (`TopPanelNeo.java:25-39`) and copies them back (`:45-54`).
- `style/neo/TopToolbarNeo.java` (52 lines) extends `TopToolbar.java` (460 lines),
  re-declares 7 fields (`TopToolbarNeo.java:24-30`), copies them back (`:44-49`) and
  repeats the read-only/one-project computation of `TopToolbar.java:116-121` in
  `TopToolbarNeo.java:37-41`.
- `TopPanel` mixes markup with logic: logo link (`TopPanel.java:105-117`), read-only label
  and delete-account hiding (`:119-123`), one-project mode (`:125-128`), the language list
  (`:72-86, 130-139, 156-163`) and `showUserEmail` (`:170-172`).
- Neo bug: the delete-account item in `style/neo/TopPanelNeo.ui.xml:72` is named
  `"Signout"`, so `accountButton.setItemVisible("DeleteAccount", false)`
  (`TopPanel.java:120`) never hides it for read-only users in neo.
- Neo's template declares `myProjects` and `viewTrash` with `<ui:with>`
  (`TopPanelNeo.ui.xml:14-15`), so they are never in the page and `TopPanel.java:126-127`
  removes unattached widgets. `<ui:with field="config">` (`:13`) is unused.

## Steps
1. `TopBarPresenter`: takes the system config, user, read-only and one-project flags;
   tells its `View` `showLogo(url)`, `showReadOnly(boolean)`,
   `showProjectLinks(boolean)`, `showLanguages(List<…>, current)`, `showUserEmail(String)`.
   Hiding delete-account is `actions.get(DELETE_ACCOUNT).setVisible(false)`, not a widget
   name, which also fixes the neo bug (unless P3-12 already did).
2. Templates per decision 0008: root `<gwt:HTMLPanel styleName="flex-row items-center …">`; the top bar
   places logo, main menu, then a `flex-row items-center justify-end grow` `<gwt:HTMLPanel>` with the links, language
   and account menus; the main menu is one template with every menu and item, in master's
   order. The menu buttons stay today's `DropDownButton`/`DropDownItem` widgets until
   P5-26; keep today's style names next to the flex classes.
3. Each main-menu view extends `Composite`, owns its `Binder`, implements
   `MainMenuPresenter.View` and exposes the anchor element the tutorial popup needs
   (replaces `getSettingsDropDown()`). Classic keeps six menus (Project, Connect, Build,
   Settings, Help, Admin; 48 items); neo keeps five (37 items) and its Help menu stays in
   `NeoTopBar` (`TopPanelNeo.ui.xml:26-62`).
4. Each top bar has `@UiField(provided = true) Widget mainMenu` filled from the menu view
   passed in. `ClassicTopBar` keeps My Projects, View Trash, Guide, Feedback links;
   `NeoTopBar` keeps its Help dropdown and drops the two phantom `<ui:with>` fields.
5. Wire in `Ode` with the P4-15 pattern (`provided = true` field from the layout). Repoint
   the remaining callers to `MainMenuPresenter`/`TopBarPresenter`; delete
   `getTopToolbar()`/`getTopPanel()`.
6. `git mv` each old template to its new path before editing, so history follows it.

- [ ] Snapshot diff shows no change in classic or neo, light or dark (read-only neo
      account menu excepted).

## Rules
- Views render and report; enable/visible/label come from actions and presenters.
- Templates follow decision 0008: every box a flex `HTMLPanel`, text as `Label`/`InlineLabel`, `addStyleNames` on components, one
  template per region (top bar, main menu).
- A layout never imports another layout.
- At most ~400 added lines and ~20 files; templates moved with `git mv`. If over, split:
  P4-19a top bars + `TopBarPresenter`, P4-19b main menus + companion logic.
- Branch `ui/p4-19-top-bar-views`; PR title `[new-ui P4-19] Each layout has its own top bar
  and menus`; commits like `refactor(views): top bar and menus per layout`; no AI
  attribution.

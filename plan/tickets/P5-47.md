## Summary
A single drag engine, `controls/behaviour/DragDrop`, runs the palette-to-viewer drag, moves in
the viewer, the non-visible strip and the sprite origin point, on Pointer Events (mouse, touch
and pen). Sources implement `Draggable`, targets implement `DropTarget` and register themselves,
and the preview comes from `Controls.dragPreview()`, so a layout can change it. `widgets/dnd/`
(827 lines) and the gwt-dnd jar are deleted. Classic and neo look as before, with one visible
change: **Escape cancels a drag** (decision 0015).

## Why
- Today's engine is `widgets/dnd/` on GWT 1.x `MouseListener`, `SourcesMouseEvents` and
  `DOM.setCapture`, deprecated since GWT 1.6; `DragSourceSupport` (609 lines) keeps the pointer
  position in `public static absX`/`absY`, which `MockTableLayout:178` and
  `MockTableArrangement:77` read.
- Targets come from hand-made depth-first lists (`DesignerEditor.java:122`, `YaFormEditor.java:115`)
  found through Ode's active editor, and the engine tests every one on each pointer move.
- The preview is whatever the source builds (`SimplePaletteItem.createDragWidget`, line 184;
  `MockComponent.createDragWidget`, line 1044; `DragSourceSupport.DragWidgetPopup`), so a layout
  has no say. Nova is expected to start a palette drag as a small card and turn it into the mock
  over the phone.
- Box dragging by `WorkAreaPanel` is dead (`docs/14-drag-and-drop.md`, problem 9) and is the only
  other user of the gwt-dnd jar. Delete `WorkAreaPanel` and the jar here unless P0-01 has
  already removed them.

## In scope
- New `controls/dnd/`: `Draggable`, `DropTarget`, `DropZone` (`NONE`, `PHONE`, `NON_VISIBLE_STRIP`,
  `TREE`, `IMAGE`), `DropPoint` (pointer position relative to the target and the grab offset,
  replacing `absX`/`absY`), `PreviewContent`, `DragPreview`.
- New `controls/behaviour/DragDrop` (the engine) and `MockDragPreview` (behaviour only: shows
  `content.mock()` at the grab point and ignores `over`, which is today's look).
- `Controls.dragPreview()` as a `default` method returning `new MockDragPreview()`; classic and
  neo do not override it.
- Pointer Events through JsInterop (`pointerdown`, `pointermove`, `pointerup`, `pointercancel`,
  `setPointerCapture`), today's 5-pixel threshold; the preview has `pointer-events: none`.
- **Escape cancels the drag**: the preview is removed, `Draggable.onDragEnd(false)` runs, no
  command runs. A cancelled touch (`pointercancel`) behaves the same.
- Sources: `SimplePaletteItem` (payload `NEW_COMPONENT`; `previewContent()` from
  `createMockComponentFromPalette()`), `MockComponent` (payload `COMPONENTS`; a `ClonedWidget`
  copy, the original hidden but keeping its space), the sprite origin point (`SPRITE_ORIGIN`);
  `MockBall`'s `onDragWidgetCreated` adjustment moves into its `previewContent()`.
- Targets: the mock containers and layouts (`MockContainer`, `MockHVLayoutBase`,
  `MockAbsoluteLayout`, `MockTableLayout`), `SimpleVisibleComponentsPanel`,
  `SimpleNonVisibleComponentsPanel`. A target registers its element when attached and
  unregisters when detached; the engine walks up from the element under the pointer to the
  nearest registered target, so the innermost container wins, then calls `accepts`, `onHover`,
  `onLeave`, `onDrop` and tells the preview `over(target.zone())` when the zone changes. Drops
  ask `ComponentRules` and run `AddComponent`/`MoveComponents` (P3-45).
- The hints' hard-coded colours (`#0000ff` in `MockHVLayoutBase:36`, the border colour in
  `MockAbsoluteLayout:99`) come from a token, `--color-drop-hint`, in each layout's `tokens.css`,
  with today's values.
- Delete `widgets/dnd/`, the editors' hand-made target lists, the `absX`/`absY` statics and the
  gwt-dnd jar (with the dead `WorkAreaPanel`, unless P0-01 did) (`lib/gwt_dragdrop/gwt-dnd-3.2.3.jar`, `YaClient.gwt.xml:24`).

## Out of scope
- The component tree's own drag (P5-48); it keeps working on HTML5 until then.
- Files dragged in from the desktop and a project row dragged out (P4-46).
- Blockly's own block drags. A different preview for nova (a later ticket; the hook is here).
- The rules and commands (P3-45).

## Steps
1. Contracts, `DragDrop` and `MockDragPreview`, with a unit test for target lookup (innermost
   wins), the 5-pixel threshold, Escape, and `pointercancel`, against a fake target. Ship as
   `(1/2)` with the palette as the first source and the viewer as the first target.
2. `(2/2)`: viewer moves, the non-visible strip, the sprite origin point, the colour token, and
   deleting `widgets/dnd/` and the jar.
3. Keep behaviour: the same drop positions in `MockAbsoluteLayout`, `MockCanvas` and
   `MockTableLayout` (they now read `DropPoint`), and the same hints.

## Acceptance criteria
- [ ] No class under `widgets/dnd/` remains; nothing imports `com.allen_sauer.gwt.dnd`; the jar
      and its `YaClient.gwt.xml` line are gone (`WorkAreaPanel` too).
- [ ] No `public static` pointer position is left; `MockTableLayout` and `MockTableArrangement`
      read `DropPoint`.
- [ ] `DragDrop`'s tests pass under `ant tests`; `core/` and `controls/dnd` import no layout.
- [ ] A palette drag, a move in the viewer, a drop in the non-visible strip and a sprite origin
      drag work with mouse, touch and pen.
- [ ] Escape during any of these drags cancels it and changes nothing.
- [ ] Snapshot diff shows no change in classic or neo, light or dark (an idle designer; the drag
      itself is checked by hand).

## Rules
- At most ~400 added lines and ~20 files per PR: ship as `(1/2)` and `(2/2)`.
- Escape is the only visible change. A layout never imports another layout.
- Short conventional commit subjects, e.g. `refactor(dnd): palette drag runs on the drag
  engine`; no AI attribution.

## How to verify
- `ant checkstyle -Dcommit=upstream/master`: no warnings on changed lines
- `ant -Dskip.ios=true noplay`, `ant tests`, `ant BlocklyTest`
- By hand, both layouts, mouse and a touch screen: drag a Button from the palette into a
  vertical arrangement (insertion line), into an absolute arrangement (drop area), onto a table
  (cell highlight) and onto a Canvas (a Ball); drag a Clock into the non-visible strip; move
  a component to another arrangement; press Escape in the middle of each.

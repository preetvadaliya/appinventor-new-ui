## Summary
The rules for each layout's pages live in its own `views/` files (decision 0010), loaded
only for the active layout: frame, top bar, panel boxes, status bar and status messages in
`views/shell.css`; the project list in `views/projects.css`; the work area and its column
sizes in `views/editor.css`. Page-wide defaults go to the shared `reset.css` (values from
tokens) and `fonts.css`. Nothing looks different.

## Why
After P4-21 each layout owns its frame views, but their rules still come from three places:
the global `war/static/css/Ya.css`, plus `layouts/classic/public/classic/variableColors.css` (classic) or
`layouts/neo/public/neo/neo.css` (neo) compiled into `Ode.Resources`. In `Ya.css`, 85 rules (~636 lines):
- 1-91 page globals (10 rules): four `@font-face` (the two Roboto ones repeat
  `war/static/css/fonts.css:1-10`; OpenDyslexic 26-36 exists only here), `body, html`
  sizing, `body` font and background (60-64), `.dyslexic *`, `body.blocklyMinimalBody`,
  icon sizing, and `.floatingBox`, which `index.jsp` (noscript and browser warning boxes)
  and `war/Ya_tos_form.html` also use, with no layout loaded
- 140-165 `.ode-Root`, `div.TopToolbar`, `div.OverDeckPanel`, `div.StatusPanel` (4 rules)
- 250-318 panel boxes `.ode-Box-*` (9); 326-436 project list `.ode-Project*` (16)
- 599-753 top bar `.ode-TopPanel*`, `.ode-Logo`, `.ode-TopToolbar` (20)
- 754-830 work area `.ode-TutorialWrapper`, `.ode-DeckPanel`, `.ode-WorkColumns` (8)
- 936-955 `.ode-StatusPanel` (2); 1944-2030 status messages: `.ode-RpcStatusMessage`,
  `.ode-ErrorMessage`/`WarningMessage`/`InfoMessage` (`ErrorReporter.java:28`),
  splitters, compiler markers (16)

About 36 rules in `variableColors.css` and 67 in `neo.css` restyle these classes; `neo.css`
also has neo-only frame rules (`body` at 17, `.ode-ProjectCheckBox`, `.ode-ProjectFolderIcon`,
`.ode-Designer-LeftColumn`, `.ode-Box-projectlist`, `.left-spacer`, `.right-spacer` …).

## Steps
1. Make each layout's `stylesheets()` return `tokens.css`, `views/shell.css`,
   `views/projects.css`, `views/editor.css` (P6-36 adds `controls.css` after `tokens.css`).
   They load after the shared files `index.jsp` links.
2. For each page rule in `Ya.css`, copy it into the matching file of both layouts (each
   layout is self-contained; no shared page file), merge that layout's override from
   `variableColors.css` or `neo.css` into it, then delete all originals. Move the neo-only
   and classic-only page rules too. Fixed sizes (box widths, column widths) go to
   `views/editor.css`, never to `layout.css`.
3. Page globals go to shared files: `body, html` sizing, `.dyslexic *`, icon sizing,
   `.floatingBox` and the `body` font and background (as `var(--font-body)`,
   `var(--color-page)` …, each layout's `tokens.css` giving today's values) to `reset.css`;
   `body.blocklyMinimalBody` to `blocks.css`; OpenDyslexic `@font-face` to `fonts.css`;
   drop the duplicate Roboto faces. Add the example's `box-sizing` reset only if the
   snapshot diff stays clean; otherwise leave it out and say so on the ticket.
4. Split shared selector lists such as `.ode-TopPanelButton, .ActionDropDown-Default` so
   only the frame half moves; leave the controls half for P6-36.
5. Rewrite `url()`s: `Ya.css:63`, `254`, `400`, `940`, `1976`, `1982` use `../images/…`
   relative to `static/css/`; from `ode/<layout>/views/` write `../../../static/images/…`,
   from `ode/features/` `../../static/images/…`.
   `neo.css:561` uses a page-relative path; check it resolves today before keeping it.

## Acceptance criteria
- [ ] `Ya.css`, `variableColors.css` and `neo.css` have no frame rule left.
- [ ] Classic loads only classic's three `views/*.css`, neo only neo's (Network panel).
- [ ] No `views/*.css` imports or refers to the other layout's folder; `reset.css` has no
      literal colour or font (only `var(--…)`, with fallbacks where the TOS page needs them).
- [ ] The terms-of-service page and the noscript box still show `.floatingBox`.
- [ ] Dyslexic font setting still switches the font.
- [ ] Snapshot diff shows no change in classic or neo, light or dark.

## Rules
- At most ~400 new lines and ~20 files. Rules moved verbatim (`git diff --color-moved`)
  do not count, but the second copy of each frame rule does. Expect two PRs:
  `(1/2)` page, top bar, work area, boxes; `(2/2)` project list, status bar, messages.
- No visual change. Fix cascade ties with specificity, never `!important`.
- A layout never imports or extends another layout, CSS included.
- Short conventional commit subjects, e.g. `refactor(css): neo page rules move to views files`;
  no AI attribution.

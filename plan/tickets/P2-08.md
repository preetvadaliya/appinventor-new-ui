## Summary
Choosing Light or Dark in Settings > User Interface Settings applies at once:
`ThemeService.setMode()` flips `data-theme` on `<html>`, saves the setting without a reload
and fires `ThemeChangedEvent`, and Blockly and the CloudDB data visualizer follow the event.
Changing the layout still saves and reloads. The only visible change is that the page no
longer reloads for a theme switch.

## Why
- The dialog's Apply (`UISettingsWizard.applySettings`, `UISettingsWizard.java:97-106`) sets
  layout and theme, then calls `Ode.saveUserDesignSettings()` (`Ode.java:1520-1531`), whose
  save callback runs `Window.Location.reload()`, even when only the theme changed.
- After P2-05 and P2-06 the colours come from `data-theme`, and after P2-07 the images follow
  `ThemeChangedEvent`; nothing sets either at run time yet.
- Code that reads the theme once:
  - `BlocksEditor.java:649` calls `blocksArea.injectWorkspace(Ode.getUserDarkThemeEnabled())`;
    `BlocklyPanel.injectWorkspace` (`BlocklyPanel.java:759-762`) passes it to `AI.inject`
    (`blocklyeditor/src/blocklyeditor.js:1158-1162`), which calls
    `setTheme(Blockly.Themes.darkTheme)` when dark and never sets the light theme back. Each
    `BlocklyPanel` has its own workspace.
  - `DataVisualizerPanel.java:130-132` (a singleton, field at line 78) and its
    `EntryEditDialog` (`DataVisualizerPanel.java:657-660`) add `cdbviz-dark` once at
    construction (rules in `war/static/css/Ya.css:534-597`).
  - `UISettingsWizard.java:64` preselects the theme from `Ode.getUserDarkThemeEnabled()`.

## In scope
- `core/theme/ThemeService.java` (from P2-07): add `setMode(ThemeMode)`: resolve `SYSTEM`
  through `matchMedia('(prefers-color-scheme: dark)')`, set `data-theme` on `<html>`, call
  `Ode.setUserDarkThemeEnabled()` and `Ode.getUserSettings().saveSettings(null)` (as
  `Ode.java:1792` does), then fire the event through `apply()`
- `wizards/UISettingsWizard.java`: Apply calls `setMode()` and closes when only the theme
  changed; when the layout changed it saves and reloads as today. Preselect from `ThemeService`.
- `editor/blocks/BlocklyPanel.java`: new JSNI `setDarkTheme(boolean)` calling
  `workspace.setTheme(dark ? Blockly.Themes.darkTheme : Blockly.Themes.Classic)`
- `editor/blocks/BlocksEditor.java`: register a handler that calls `setDarkTheme`; remove it in
  `onClose()` (`BlocksEditor.java:468`); line 649 reads `ThemeService`
- `blocklyeditor/src/blocklyeditor.js:1158-1162`: `AI.inject` sets the light theme when not dark
- `editor/simple/dialogs/DataVisualizerPanel.java`: toggle `cdbviz-dark` on the event for the
  panel; `EntryEditDialog` reads `ThemeService` when it opens
- `Ode.java`: `saveUserDesignSettings()` keeps its reload, documented as "layout changes only"

## Out of scope
- Offering System in the dialog and storing it (needs a new setting value and a translated
  label; `setMode(SYSTEM)` works, nothing calls it yet)
- Switching layout without a reload (stays a reload by decision 0001)
- The dyslexic-font reload (`setUserDyslexicFont`, `Ode.java:1415-1430`)
- The neo welcome tip's reload (`Ode.java:1786-1789`): it changes layout

## Steps
1. Add `setMode()` and its `data-theme` and save logic.
2. Change `applySettings()`: compare the chosen layout with `UserPreferences.layout()`; only
   reload when it differs. Cancel keeps restoring the layout preference as today
   (`UISettingsWizard.java:91-94`).
3. Add `BlocklyPanel.setDarkTheme()` and the `AI.inject` else branch; make every open
   `BlocksEditor` follow the event, including hidden screens.
4. Make `DataVisualizerPanel` follow the event.
5. Grep for any remaining `getUserDarkThemeEnabled()` reader outside boot and switch it to
   `ThemeService.get().isDark()`.

## Acceptance criteria
- [ ] Switching Light <-> Dark in the dialog repaints colours, logo, phone frames, icons and
      the blocks workspace with no reload, in classic and neo.
- [ ] A reload after switching keeps the chosen theme (the setting was saved).
- [ ] Changing the layout in the same dialog still reloads into the new layout.
- [ ] A blocks workspace opened after a switch, and one opened before it, both show the
      current theme; switching back to light restores Blockly's light theme.
- [ ] `Ode.getUserDarkThemeEnabled()` is only read at boot.
- [ ] Snapshot diff shows no change in classic or neo, light or dark (each run still loads
      its theme from `?ui=`).

## Summary
The dialogs that are built inline with `new DialogBox(...)` outside the wizards move
into `features/dialogs/` and are built from controls, so classic and neo each draw them
with their own controls. Users see no change.

## Why
P5-28 and P5-29 cover the wizards and the dialogs in `explorer/commands`, but about 26
dialogs are still assembled by hand with raw GWT widgets, most of them inside `Ode.java`:
13 `new DialogBox(` at `Ode.java:1661, 1723, 1839, 1967, 2006, 2067, 2119, 2144, 2169,
2187, 2259, 2293, 2330` (empty trash, welcome, survey, session dead, invalid session,
bash warning, final, gallery loading, corruption, blocks truncated, generic warning,
won't connect, disabled account). Until they move, a layout cannot restyle them and
`Ode.java` keeps UI code it should not own.

## Steps
1. Re-count `new DialogBox(` across `client/` and compare with the list above; add any
   dialog this list misses to the ticket before starting.
2. For each dialog, create a class in `features/dialogs/<area>/` that extends
   `SharedView` and uses `controls:Dialog` and `controls:Button`; move its text and handlers over
   unchanged.
3. Replace the inline construction with a call to the new class.
4. Split into two PRs if needed: `Ode.java` dialogs first, the rest second.

## Acceptance criteria
- [ ] No `new DialogBox(` remains in `Ode.java`.
- [ ] Every dialog listed above is a class in `features/dialogs/`, built from controls.
- [ ] Texts, buttons, autohide and modal flags are unchanged for each dialog.
- [ ] Snapshot diff shows no change in classic or neo, light or dark (welcome, empty trash
      and won't-connect dialogs at least).

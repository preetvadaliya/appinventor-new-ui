## Summary
"Can component X go into container Y?" is answered once, in `core/dnd/ComponentRules`, and the
two things a drop does become commands in `features/designer/`: `AddComponent` and
`MoveComponents`. A new `core/dnd/DragPayload` says what is dragged. The viewer drop, the tree,
paste, Enter and double-click on a palette item, and Alt+Up/Down all ask the rule and run the
command. Users see no change.

## Why
- The question has four answers today (`docs/14-drag-and-drop.md`, "What is wrong with it", 1):
  `MockContainer.acceptableSource` with `instanceof` checks (`MockSprite`, `MockMapFeature`,
  `MockChartData`); `MockContainer.willAcceptComponentType` with type lists, for the tree and
  paste; `SimpleNonVisibleComponentsPanel.onDragEnter` and `SimpleVisibleComponentsPanel.onDragEnter`
  with `instanceof SimplePaletteItem`; and `SimplePaletteItem.addComponent`. They can disagree and
  none can be unit-tested.
- Rules sit inside widgets: `MockContainer.onDrop` asks whether it is a `MockAbsoluteArrangement`
  and whether its editor is a `YaFormEditor`; `SimplePaletteItem.addComponent` finds the form
  through `getDropTargets()[0]`.
- The keyboard paths (Enter, double-click, Alt+Up/Down) are separate code, so they drift from the
  drag paths.

## In scope
- New `core/dnd/ComponentRules.java`: `canContain(containerType, childType)` (Canvas: sprites only;
  Map: map features only; Chart: chart data only; the rest: none of those) and
  `canHoldNonVisible(containerType)`; a unit test with every container type.
- New `core/dnd/DragPayload.java`: a plain value with `Kind` `NEW_COMPONENT`, `COMPONENTS`,
  `SPRITE_ORIGIN`, the component type and the component names; factories `newComponent(type)`,
  `components(names)`.
- New `features/designer/AddComponent.java` and `MoveComponents.java`: the commands a drop and the
  keyboard both run; they use mocks only.
- Callers: `MockContainer.acceptableSource`, `willAcceptComponentType`, `onDrop`,
  `SimpleNonVisibleComponentsPanel.onDragEnter`, `SimpleVisibleComponentsPanel.onDragEnter`,
  `SimplePaletteItem.addComponent`, the tree's drop and Alt+Up/Down in `SourceStructureExplorer`,
  and paste, so that each asks `ComponentRules` and runs a command.

## Out of scope
- The drag engine, previews and the tree's drag (P5-47, P5-48); file drops (P4-46).
- Moving the `Mock*` classes (P7-39).

## Steps
1. Write `ComponentRules` from the four existing answers; list every pair on which they
   disagree today in the PR description and say which answer won and why.
2. Write `DragPayload`, then the two commands, moving the code out of `MockContainer.onDrop` and
   `SimplePaletteItem.addComponent`.
3. Point each caller at the rule and the commands. Keep behaviour: a drop that was refused
   stays refused, unless the old paths disagreed and the PR description says so.

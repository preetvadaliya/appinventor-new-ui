## Summary
Classic and neo each get their own controls for buttons, icon buttons, menu buttons, toolbars
and icons (`layouts/classic/controls/`, `layouts/neo/controls/`). `Layout.controls()` returns it, boot
installs it with `Controls.install(layout.controls())`, and every layout view from P4 builds its
buttons and menus from its own control classes. Users see no change.

## Why
- Today both layouts draw every button and menu with the same `widgets/TextButton` and
  `widgets/DropDownButton`; they differ only by CSS class and an `icon=` attribute. Neo's
  templates name glyphs (`icon="inventory_2"`, `style/neo/TopToolbarNeo.ui.xml:18`;
  `icon='add'`, `style/neo/ProjectToolbarNeo.ui.xml:18`); classic's templates have none.
- `DropDownButton.setCaption` (line 528) always renders icon + caption + " ▾ "
  (`makeText`, line 293); `TextButton.makeText` (line 77) renders icon + caption.
- Controls elements in today's templates (their P4 views carry the same set):
  classic `TopToolbar.ui.xml` 6 menu buttons / 48 items, `TopPanel.ui.xml` 2 / 2 plus 4
  `TextButton`, `ProjectToolbar.ui.xml` 1 toolbar / 10 items, `DesignToolbar.ui.xml`
  1 toolbar / 8 items / 1 menu button, `explorer/folder/ProjectFolder.ui.xml` 2 icons;
  neo `TopToolbarNeo.ui.xml` 1 toolbar / 5 menu buttons / 37 items, `TopPanelNeo.ui.xml`
  3 / 13, `ProjectToolbarNeo.ui.xml` 1 toolbar / 12 items / 1 menu button / 2 items,
  `DesignToolbarNeo.ui.xml` 1 toolbar / 10 items / 1 menu button,
  `ProjectFolderNeo.ui.xml` 2 icons, `YaVisibleComponentsPanelNeo.ui.xml` 3 icons.
- Classic is not icon-free: `ProjectFolder.ui.xml:17-18` shows the `folder` and
  `chevron_right` Material glyphs. Classic's icon map must keep those two.

## Steps
1. Each layout control is its own template plus behaviour-only Java (decision 0008):
   `ClassicButton.ui.xml` + `ClassicButton.java`, and so on. Shared behaviour (action
   binding, keyboard, ARIA) comes from `controls/behaviour`; a control may delegate to the
   matching `Standard*` class for behaviour, never copy its markup.
   `NeoButton`/`NeoMenuButton` render the layout's glyph for the action's `IconKey`, then
   the label; `ClassicButton`/`ClassicMenuButton` render the label only; both menu buttons
   keep the trailing " ▾ ". Keep today's class names (`ode-TextButton`,
   `ode-TopPanelButton`, `ya-Toolbar`, `ode-ContextMenu`) so the CSS still matches.
2. Icon-only buttons put the action label into `aria-label` (decision 0004).
3. `ClassicControls` and `NeoControls` implement `Controls`; each returns its own pieces and,
   for any piece it has not written yet, the `Standard*` one. Neither imports the other.
4. Add `Controls controls()` to `Layout` (if P1-04 left it out) and implement it in both layouts.
   In `LayoutRegistry`, call `Controls.install(layout.controls())` after the stylesheets are added
   and before any presenter creates a view (`docs/03-layouts.md`, boot step 4).
5. In each P4 template, swap `xmlns:ai="urn:import:…client.widgets"` elements for the
   layout's own classes (`<c:NeoMenuButton action="…">`, `<c:ClassicButton action="…"/>`)
   with `xmlns:c="urn:import:…client.layouts.neo.controls"` (or `.classic.controls`). Replace
   `icon="glyph"` attributes with the action's `IconKey`.
6. Update `@UiField` types in the view classes to the control interfaces.

## Acceptance criteria
- [ ] No template under `layouts/` names `client.widgets` or `client.components`.
- [ ] `layouts/classic/**` imports nothing from `layouts/neo/**` and the reverse.
- [ ] `Controls.active()` is `ClassicControls` when `UiLayout=CLASSIC` and `NeoControls` when `NEO`.
- [ ] Every icon-only button has an `aria-label`.
- [ ] Menus open, navigate and close by keyboard exactly as before (MenuKeyboard).
- [ ] Snapshot diff shows no change in classic or neo, light or dark.

## Rules
- At most ~400 added lines and ~20 files. If it goes over, land classic and neo as two
  PRs (classic first); the second must not change `layouts/classic/`.
- No visual change.
- A layout never imports or extends another layout; it may use `controls/standard` only.
- Short conventional commit subjects, e.g. `refactor(controls): neo draws its own buttons`;
  no AI attribution.
